## Module 1 — Introduction, efficiency analysis and brute force

> **In short:** an **algorithm** is a precise, finite set of steps. We compare algorithms by how their running time grows with input size, written in **O, Ω and Θ** notation. **Brute force** tries the obvious approach first (selection sort, sequential search).

### What an algorithm is

An **algorithm** is a finite sequence of unambiguous instructions that solves a problem for every legitimate input in a finite amount of time. Example: **Euclid's algorithm** — `gcd(m, n) = gcd(n, m mod n)` until n = 0.

### Algorithmic problem solving

Understand the problem → decide on the computational model, exact vs approximate solution, and a **design technique** → choose data structures → specify the algorithm (pseudocode, flowchart) → **prove correctness** → **analyse** time and space → code it.

Important problem types: sorting, searching, string processing, graph problems, combinatorial problems, geometric and numerical problems.

### Analysis framework

Measure efficiency by the **input size** n and the number of times the **basic operation** executes, C(n), instead of seconds. Distinguish **worst-case**, **best-case** and **average-case** efficiency (and amortised efficiency for sequences of operations). The **order of growth** matters for large n: log n < n < n log n < n² < n³ < 2ⁿ < n!.

### Asymptotic notations

- **O(g(n))** — upper bound: t(n) ≤ c·g(n) for all n ≥ n₀.
- **Ω(g(n))** — lower bound: t(n) ≥ c·g(n) for all n ≥ n₀.
- **Θ(g(n))** — tight bound: c₂·g(n) ≤ t(n) ≤ c₁·g(n).

Useful: if t₁ ∈ O(g₁) and t₂ ∈ O(g₂) then t₁ + t₂ ∈ O(max(g₁, g₂)). Compare growth with the **limit** of t(n)/g(n): 0 → smaller order, a constant → same order, ∞ → larger order.

### Analysing non-recursive algorithms

1. Choose the input-size parameter. 2. Identify the basic operation (usually in the innermost loop). 3. Check whether worst/best/average cases differ. 4. Write a **sum** for the number of executions. 5. Simplify it.

Example — largest element: one comparison per element after the first, C(n) = n − 1 ∈ Θ(n). Checking whether all elements are unique: Σᵢ Σⱼ 1 = n(n−1)/2 ∈ Θ(n²) in the worst case. Matrix multiplication: n³ multiplications.

### Analysing recursive algorithms

Set up a **recurrence** for the count and an **initial condition**, then solve it, usually by **backward substitution**.

- Factorial: M(n) = M(n−1) + 1, M(0) = 0 → M(n) = n.
- Tower of Hanoi: M(n) = 2M(n−1) + 1, M(1) = 1 → M(n) = 2ⁿ − 1.
- Binary digits of n: A(n) = A(⌊n/2⌋) + 1 → Θ(log n).

### Brute force

A straightforward approach directly based on the problem statement.

- **Selection sort** — find the minimum of the unsorted part and swap it to the front. Always n(n−1)/2 comparisons → Θ(n²); only n − 1 swaps.
- **Bubble sort** — swap adjacent out-of-order pairs; the largest "bubbles" to the end each pass. Θ(n²) comparisons; with an early-exit flag the best case is Θ(n).
- **Sequential search** — compare with each element; worst case n comparisons. Placing the key as a **sentinel** at the end removes the bounds check.
- **Brute-force string matching** — try aligning the pattern at every position; worst case m(n − m + 1) comparisons → O(nm).

## Module 2 — Exhaustive search, decrease-and-conquer, divide-and-conquer

> **In short:** **exhaustive search** tries every candidate. **Decrease-and-conquer** solves a smaller instance and extends it (insertion sort, DFS, BFS, topological sort). **Divide-and-conquer** splits the problem, solves the parts and combines them (merge sort, quick sort).

```flow
Divide into subproblems -> Conquer each recursively -> Combine the answers
```

### Exhaustive search

Generate every candidate solution and pick the best.

- **Travelling salesman:** try all tours — (n − 1)!/2 distinct ones → impractical beyond small n.
- **Knapsack:** try all 2ⁿ subsets of items, keep the most valuable one within capacity.

### Decrease-and-conquer

Reduce the problem to one smaller instance (by a constant, by a constant factor, or by a variable amount), solve it, extend the solution.

- **Insertion sort** — insert A[i] into the already sorted A[0..i−1]. Worst case Θ(n²) (reverse order), best case Θ(n) (already sorted), average ≈ n²/4. Excellent for nearly sorted data.
- **Topological sorting** of a DAG — order vertices so every edge goes from earlier to later. Two methods: **DFS** (reverse of the order in which vertices become dead ends) or **source removal** (repeatedly remove a vertex with no incoming edges). A cycle means no topological order exists.

### Divide-and-conquer

Divide into subproblems of the same type, solve them recursively, combine the solutions. Running time follows **T(n) = a·T(n/b) + f(n)**, solved with the **Master theorem** for f(n) ∈ Θ(n^d):

- a < b^d → Θ(n^d); a = b^d → Θ(n^d log n); a > b^d → Θ(n^(log_b a)).

**Merge sort:** split in half, sort each, merge. T(n) = 2T(n/2) + Θ(n) → **Θ(n log n)** in all cases; stable; needs Θ(n) extra space.

**Quick sort:** choose a **pivot**, **partition** so smaller elements are left and larger right, recurse on both parts.

- Best/average: **Θ(n log n)** (about 1.39 n log₂ n comparisons on average).
- Worst: **Θ(n²)** when the pivot is always the smallest or largest (e.g. already sorted input with the first element as pivot). Fixes: median-of-three or random pivot. In place, not stable.

**Binary tree traversals** (preorder, inorder, postorder) are natural divide-and-conquer algorithms; the height of a tree is h(T) = max(h(Tₗ), h(Tᵣ)) + 1 with h(∅) = −1.

**Multiplication of large integers:** split each n-digit number into halves, a = a₁a₀ and b = b₁b₀. Then
c₂ = a₁b₁, c₀ = a₀b₀, c₁ = (a₁ + a₀)(b₁ + b₀) − (c₂ + c₀),
so only **3** multiplications of half-size numbers are needed: M(n) = 3M(n/2) → **Θ(n^1.585)** instead of n².

**Strassen's matrix multiplication** multiplies two 2 × 2 block matrices with **7** multiplications instead of 8 (using the seven products m₁…m₇), giving M(n) = 7M(n/2) → **Θ(n^2.807)**.

## Module 3 — Transform-and-conquer and space–time trade-offs

> **In short:** **transform-and-conquer** changes the problem into an easier one first (presorting, heaps and heapsort). **Space–time trade-offs** spend extra memory to save time (counting sort, input enhancement in string matching, hashing).

### Transform-and-conquer

Transform the instance into an easier one (**instance simplification**), a different representation (**representation change**), or a different problem (**problem reduction**).

### Balanced search trees

A plain BST can degrade to height n − 1. Balanced trees keep height O(log n):

- **AVL tree** — for every node, the **balance factor** = height(left) − height(right) ∈ {−1, 0, 1}. After an insertion breaks balance, one of four **rotations** restores it: single right (**R**), single left (**L**), double left-right (**LR**), double right-left (**RL**). Search, insert and delete are Θ(log n).
- **2-3 tree** — every node holds one key (2-node) or two keys (3-node) and **all leaves are at the same level**. Insertion adds to a leaf; a leaf that would hold three keys **splits** and pushes the middle key up, possibly up to the root. Height between log₃ n and log₂ n.

### Heaps and heapsort

A **max-heap** is a complete binary tree (stored in an array, children of i at 2i and 2i+1) where each key ≥ its children.

- **Bottom-up construction:** for each parental node from the last one up to the root, sift its key down until the heap property holds — Θ(n).
- **Delete max:** swap the root with the last key, shrink the heap, sift the new root down — O(log n).
- **Heapsort:** build a heap, then delete the maximum n − 1 times, placing each at the end. **Θ(n log n)** in all cases, in place, not stable.

### Space–time trade-offs: sorting by counting

**Comparison counting sort:** for each element, count how many elements are smaller; that count is its position in the sorted array. Θ(n²) comparisons but linear moves. **Distribution counting** (for a small range of integer values) counts the frequency of each value, turns frequencies into positions, and places elements — Θ(n).

### Input enhancement in string matching: Horspool's algorithm

Compare the pattern with the text **right to left**. On a mismatch (or a full match), **shift** the pattern by a value from a **shift table** built in advance:

- t(c) = m (pattern length) if character c is not among the first m − 1 pattern characters;
- otherwise t(c) = distance from the **rightmost** occurrence of c among those m − 1 characters to the pattern's end.

The shift is determined by the text character aligned with the **last** pattern character. Worst case Θ(nm), but much faster on average for random text.

## Module 4 — Dynamic programming and greedy methods

> **In short:** **dynamic programming** solves overlapping subproblems once and stores the answers in a table (knapsack, Warshall, Floyd). The **greedy** method picks the best-looking choice at each step (Prim, Kruskal, Dijkstra, Huffman) and works when local best choices lead to a global best.

### Dynamic programming

Solve problems with **overlapping subproblems** by solving each subproblem once and storing its result in a table; requires **optimal substructure**.

**Three basic examples:**

- **Coin-row problem:** F(n) = max(cₙ + F(n−2), F(n−1)), F(0) = 0, F(1) = c₁.
- **Change-making:** F(n) = min over coins dⱼ ≤ n of F(n − dⱼ) + 1.
- **Coin-collecting robot** on a grid: F(i, j) = max(F(i−1, j), F(i, j−1)) + cᵢⱼ.

**0/1 knapsack:** with V[i, j] = best value using the first i items and capacity j,
V[i, j] = max(V[i−1, j], vᵢ + V[i−1, j − wᵢ]) if wᵢ ≤ j, else V[i−1, j]; V[0, j] = V[i, 0] = 0.
Fill the table row by row — Θ(nW) — then **backtrace** to find which items were taken. A **memory function** (top-down recursion with a table) computes only the entries actually needed.

**Warshall's algorithm (transitive closure):**
R⁽ᵏ⁾[i, j] = R⁽ᵏ⁻¹⁾[i, j] **or** (R⁽ᵏ⁻¹⁾[i, k] **and** R⁽ᵏ⁻¹⁾[k, j]) — Θ(n³).

**Floyd's algorithm (all-pairs shortest paths):**
D⁽ᵏ⁾[i, j] = min(D⁽ᵏ⁻¹⁾[i, j], D⁽ᵏ⁻¹⁾[i, k] + D⁽ᵏ⁻¹⁾[k, j]) — Θ(n³); works with negative edges but not negative cycles. Show every matrix D⁽⁰⁾ … D⁽ⁿ⁾ in an exam answer.

### Greedy method

Build a solution step by step, each time taking the choice that looks best now (**feasible, locally optimal, irrevocable**). Correct only for problems with the greedy-choice property.

- **Prim's algorithm (MST):** grow one tree from any vertex, repeatedly adding the **cheapest edge** to a vertex not yet in the tree. With a min-heap and adjacency lists, O(|E| log |V|).
- **Kruskal's algorithm (MST):** sort all edges by weight and add each edge that does **not create a cycle**, checked with **union–find**. O(|E| log |E|).
- **Dijkstra's algorithm (single-source shortest paths, non-negative weights):** repeatedly pick the unvisited vertex with the smallest tentative distance and **relax** its edges: d(v) = min(d(v), d(u) + w(u, v)). O(|E| log |V|) with a heap. Fails with negative edge weights.
- **Huffman trees and codes:** start with one-node trees weighted by symbol frequency; repeatedly **merge the two smallest-weight trees**. Left edges = 0, right = 1; the resulting **prefix-free** codes minimise the expected code length. Show the tree and the code table, and compute the average bits per symbol.

## Module 5 — Limitations of algorithmic power and coping strategies

> **In short:** some problems have proven lower bounds, and the **NP-complete** problems have no known fast algorithm. For hard problems we use **backtracking**, **branch-and-bound** or **approximation algorithms** to get answers in practice.

### Lower bounds and decision trees

A **lower bound** is the least work any algorithm for a problem must do. A **decision tree** models comparison-based algorithms: each internal node is a comparison, each leaf an outcome. A tree with l leaves has height ≥ ⌈log₂ l⌉, so:

- comparison **sorting** needs at least ⌈log₂ n!⌉ ≈ n log₂ n comparisons in the worst case — merge sort and heapsort are asymptotically optimal;
- **searching** a sorted array needs at least ⌈log₂(n + 1)⌉ comparisons — binary search is optimal.

### P, NP and NP-complete problems

- **P** — decision problems solvable in **polynomial time** by a deterministic algorithm.
- **NP** — decision problems whose candidate solution can be **verified** in polynomial time (equivalently, solvable by a nondeterministic polynomial algorithm). P ⊆ NP; whether P = NP is open.
- A problem is **NP-complete** if it is in NP and **every** NP problem **reduces** to it in polynomial time. Examples: CNF-satisfiability (the first, by Cook's theorem), Hamiltonian circuit, decision versions of TSP and knapsack, graph colouring.
- **NP-hard** problems are at least as hard as NP-complete ones but need not be in NP (e.g. the optimisation versions).

If any NP-complete problem had a polynomial algorithm, then P = NP.

### Backtracking

Build a solution one component at a time and **abandon a partial solution** (prune the branch) as soon as it cannot lead to a valid solution, exploring a **state-space tree** depth-first.

- **n-Queens:** place one queen per row; backtrack when a queen in the current row would share a column or diagonal with an earlier one. Draw the state-space tree for n = 4 (solutions 2-4-1-3 and 3-1-4-2).
- **Subset-sum:** find subsets of {s₁…sₙ} (sorted ascending) summing to d; prune a node if the current sum + next element > d, or if the current sum + all remaining elements < d.

### Branch-and-bound

For optimisation problems: at each node of the state-space tree compute a **bound** on the best value obtainable from that node; prune nodes whose bound cannot beat the **best solution found so far**, or that are infeasible. Explore the most promising node first (**best-first**).

**Knapsack:** order items by value/weight ratio; a node's **upper bound** ub = v + (W − w) × (v_{next}/w_{next}), where v and w are the value and weight already chosen. Expand the live node with the largest ub.

### Approximation algorithms for NP-hard problems

When exact solutions are too slow, accept a near-optimal one with a guaranteed **accuracy ratio** r = f(s_a)/f(s*) (for minimisation).

**Knapsack approximation:** a **greedy** algorithm takes items in decreasing value/weight order while they fit. Taking the better of that answer and the single most valuable item gives at least half the optimum. For the **continuous (fractional) knapsack**, the greedy algorithm is exact. Approximation schemes (Sahni) achieve any accuracy 1 + 1/k at a polynomial cost in n for fixed k.
