## Module 1 — Boolean algebra, maps and Verilog basics

> **In short:** digital circuits work with 0 and 1. **Boolean algebra** gives the rules to simplify expressions, a **K-map** simplifies them by grouping 1s, and **NAND/NOR** gates can build any circuit. **Verilog** describes the circuit as text.

### Binary logic

**Binary logic** works with variables that take one of two values (1/0, true/false) and three basic operations:

- **AND:** x·y = 1 only if both are 1.
- **OR:** x + y = 1 if either is 1.
- **NOT:** x′ is the complement.

In circuits, a voltage range stands for each value. A **truth table** lists the output for every input combination; n inputs give 2ⁿ rows.

### Basic theorems and properties of Boolean algebra

| Postulate / theorem | OR form | AND form |
|---|---|---|
| Identity | x + 0 = x | x · 1 = x |
| Complement | x + x′ = 1 | x · x′ = 0 |
| Idempotence | x + x = x | x · x = x |
| Null element | x + 1 = 1 | x · 0 = 0 |
| Involution | (x′)′ = x | |
| Commutative | x + y = y + x | xy = yx |
| Associative | x + (y + z) = (x + y) + z | x(yz) = (xy)z |
| Distributive | x + yz = (x + y)(x + z) | x(y + z) = xy + xz |
| **De Morgan** | (x + y)′ = x′y′ | (xy)′ = x′ + y′ |
| Absorption | x + xy = x | x(x + y) = x |

- **Duality:** swap AND and OR, and 0 and 1, in any identity and the result is also an identity.
- **Operator precedence:** parentheses, then NOT, then AND, then OR.

### Boolean functions

A **Boolean function** can be written as an expression, a truth table or a circuit. Simplifying the expression (fewer **literals** and terms) gives a cheaper circuit.

- **Minterm** mᵢ: an AND term containing every variable once, equal to 1 for exactly one row.
- **Maxterm** Mᵢ: an OR term equal to 0 for exactly one row. Mᵢ = mᵢ′.
- **Canonical forms:**
  - **Sum of minterms:** F = Σm(1, 4, 7).
  - **Product of maxterms:** F = ΠM(0, 2, 3, 5, 6).
  - The two lists are complementary.
- **Standard forms:** SOP (sum of products) and POS (product of sums), not necessarily with every variable in each term.

### Digital logic gates

The gates are AND, OR, NOT (inverter), buffer, **NAND**, **NOR**, **XOR** (x ⊕ y = x′y + xy′, which is 1 when the inputs differ) and **XNOR** (the equivalence function).

NAND and NOR are **universal gates**: any function can be built from NAND alone, or from NOR alone. Know the symbol and truth table of each gate.

### The map method (K-map)

A **Karnaugh map** is a truth table arranged so that adjacent cells differ in **one variable** (Gray-code order 00, 01, 11, 10). Grouping adjacent 1s removes the variable that changes within the group.

- **Two- and three-variable maps:** groups of 1, 2 or 4 cells. The left and right edges are adjacent.
- **Four-variable map:** 16 cells. Groups of 1, 2, 4, 8 or 16 cells. All four edges wrap around, so the four corners are adjacent.
- **Prime implicant:** the largest possible group. An **essential prime implicant** covers a 1 that no other prime implicant covers.
- **Procedure:**
  1. Take all essential prime implicants.
  2. Cover the remaining 1s with as few, as large groups as possible.
- **POS from the map:** group the **0s** to get F′ in SOP form, then complement with De Morgan's law.

```flow
Truth table -> Fill K-map -> Group 1s (largest groups, wrap edges) -> Write one term per group -> Simplified SOP
```

### Don't-care conditions

Some input combinations never occur, or their output does not matter. An example is BCD codes 1010–1111. Mark them **X** (or d).

- Include an X in a group only when it makes the group **larger**. Otherwise treat it as 0.
- Write the function as F = Σm(…) + d(…).

### NAND and NOR implementation

**Two-level NAND (from SOP):**

1. Draw the AND–OR circuit.
2. Replace every gate with NAND. Bubbles cancel by De Morgan's law.
3. A single literal feeding the second level needs an inverter.

**Two-level NOR (from POS):** draw OR–AND, then replace every gate with NOR.

**Multilevel circuits:** convert AND to NAND and OR to an inverted-input NAND, adding inverters where bubbles don't pair.

### Verilog: a model of a simple circuit

A **hardware description language (HDL)** describes hardware in text, for simulation and synthesis. In a **structural (gate-level)** model, you instantiate primitive gates:

```verilog
module simple_circuit (output D, E, input A, B, C);
  wire w1;
  and G1 (w1, A, B);   // w1 = A·B
  not G2 (E, C);       // E = C'
  or  G3 (D, w1, E);   // D = w1 + E
endmodule
```

- A module begins with **module** and ends with **endmodule**, and declares its ports as input or output.
- **wire** declares internal connections.
- In a gate primitive, the output comes first, then the inputs.
- Delays can be added: and #(30) G1 (w1, A, B);.
- **Dataflow** style uses continuous assignment: assign D = (A & B) | ~C;.

## Module 2 — Combinational and sequential logic

> **In short:** a **combinational** circuit's output depends only on today's inputs (adders, decoders, multiplexers). A **sequential** circuit also remembers the past using **latches** and **flip-flops**, which change state on a clock edge.

### Combinational circuits and the design procedure

In a **combinational circuit**, outputs depend only on the **present inputs**; it has no memory. Design steps:

```flow
Specification -> Inputs and outputs -> Truth table -> K-map for each output -> Logic diagram -> Verify
```

1. Work out the number of inputs and outputs from the specification and name them.
2. Write the **truth table**.
3. Simplify each output with K-maps.
4. Draw the logic diagram and verify it.

**Example: BCD to excess-3 code converter.**

- 4 inputs, 4 outputs.
- Inputs 1010–1111 are don't-cares.
- Each output gets its own K-map.

### Binary adder–subtractor

- **Half adder:** adds two bits. S = x ⊕ y; C = xy.
- **Full adder:** adds three bits (x, y and a carry in z).
  - S = x ⊕ y ⊕ z; C = xy + z(x ⊕ y).
  - It can be built from two half adders and an OR gate.
- **4-bit ripple-carry adder:** four full adders in a chain. The carry ripples through, so the delay grows with the number of bits.
- **Carry look-ahead:**
  - Define **generate** Gᵢ = AᵢBᵢ and **propagate** Pᵢ = Aᵢ ⊕ Bᵢ.
  - Then Cᵢ₊₁ = Gᵢ + PᵢCᵢ. Substituting repeatedly removes the ripple:
    - C₁ = G₀ + P₀C₀
    - C₂ = G₁ + P₁G₀ + P₁P₀C₀
    - C₃ = G₂ + P₂G₁ + P₂P₁G₀ + P₂P₁P₀C₀
  - Each carry is a sum of products, so once G and P are ready it takes two gate levels (AND then OR) in a 4-bit block. Wider adders need gates with many inputs, so they are built from 4-bit blocks with a second level of look-ahead.
- **Adder–subtractor:** XOR each B bit with a mode input M, and feed M into the first carry in.
  - M = 0 gives A + B.
  - M = 1 gives A + B′ + 1 = A − B (two's complement).
  - **Overflow** = Cₙ ⊕ Cₙ₋₁.

### Decoders and encoders

- **Decoder (n-to-2ⁿ):** activates exactly one of 2ⁿ outputs, which are the minterms of the inputs.
  - An **enable** input controls it; NAND-based decoders have active-low outputs.
  - **Uses:** implement any function as an OR of the decoder outputs for its minterms. Two 3×8 decoders make a 4×16 decoder.
- **Encoder (2ⁿ-to-n):** the inverse; the output is the code of the active input. The 8-to-3 encoder is the example.
- **Priority encoder:** when several inputs are 1, the highest-priority input wins. A **valid** output V shows that some input is active. Know the 4-input truth table and K-maps.

### Multiplexers

A **multiplexer (MUX)** selects one of 2ⁿ data inputs, steered by n **select lines**, and sends it to a single output.

- A 4×1 MUX gives Y = S₁′S₀′I₀ + S₁′S₀I₁ + S₁S₀′I₂ + S₁S₀I₃.
- **Implementing a function with a MUX:**
  1. An n-variable function needs a 2ⁿ⁻¹×1 MUX.
  2. Use n − 1 variables as the select lines.
  3. Feed each data input with 0, 1, the last variable or its complement, as the truth table requires.
- **Three-state gates:** have outputs 0, 1 or high impedance. They build bus multiplexers.
- **Demultiplexer:** one input sent to one of many outputs. This is a decoder with an enable input.

### HDL models of combinational circuits

**Adder** (dataflow, 4-bit):

```verilog
module adder4 (output [3:0] S, output C4, input [3:0] A, B, input C0);
  assign {C4, S} = A + B + C0;   // the 5-bit left side makes the sum 5 bits wide, so the carry lands in C4
endmodule
```

**Multiplexer** (behavioural, 2×1):

```verilog
module mux2 (output reg Y, input A, B, sel);
  always @(A or B or sel)
    if (sel) Y = B; else Y = A;
endmodule
```

The same can be written as dataflow: assign Y = sel ? B : A;.

**Encoder:** use **case** inside an always block. A casex statement with don't-care bits handles a priority encoder.

**Modelling styles:**

- **Gate-level:** primitive gates.
- **Dataflow:** assign statements.
- **Behavioural:** always blocks. A signal assigned inside an always block must be declared **reg**.

### Sequential circuits

In a **sequential circuit**, outputs depend on the inputs **and the stored state**: combinational logic plus storage elements.

- **Synchronous** sequential circuits change state only at **clock** edges (clocked sequential circuits).
- **Asynchronous** sequential circuits change state whenever the inputs change.

### Storage elements: latches

- **SR latch (NOR):**
  - S = 1 sets Q = 1; R = 1 resets Q = 0; S = R = 0 holds the state.
  - **S = R = 1 is forbidden.**
  - The NAND version has active-low inputs.
- **SR latch with control (enable):** the inputs only matter when En = 1.
- **D latch:** D connects to S and D′ to R, which removes the forbidden state. When En = 1, Q follows D (it is **transparent**). When En = 0, it holds.

### Storage elements: flip-flops

A **flip-flop** changes state only on a clock **edge**. This removes the transparency problem latches have.

- **Edge-triggered D flip-flop:**
  - Built as a **master–slave** pair of D latches, or with three SR latches.
  - Q(t + 1) = D.
  - **Timing:** **setup time** (D stable before the edge), **hold time** (D stable after the edge) and **propagation delay**.
- **JK flip-flop:**
  - J = K = 0 holds; J = 1 sets; K = 1 resets; **J = K = 1 toggles**.
  - Q(t + 1) = JQ′ + K′Q.
- **T flip-flop:** T = 1 toggles, T = 0 holds. Q(t + 1) = T ⊕ Q.
- **Characteristic tables and equations:** know the table and equation for each flip-flop above.
- **Excitation tables:** used to design counters.
- **Direct inputs:** asynchronous **preset** and **clear** force the state regardless of the clock.

## Module 3 — Basic structure of computers and machine instructions

> **In short:** a computer has five units: **input, memory, ALU, control and output**. A program is a list of instructions in memory; the processor **fetches, decodes and executes** them one by one. Speed is given by **T = (N × S) / R**.

### Functional units

A computer has five functional units:

- **Input:** keyboard, mouse and other devices.
- **Memory:** **primary** memory (RAM, organised in **words**, each with an address; access time is the same for any location, so it is *random access*), **cache**, and **secondary** storage (disks).
- **ALU (arithmetic and logic unit):** performs operations on operands held in **registers**.
- **Control unit:** generates timing and control signals that coordinate the other units.
- **Output:** display, printer and other devices.

The ALU and control unit together form the **processor**.

### Basic operational concepts

A program is a sequence of instructions held in memory (the **stored-program** concept). Key processor registers:

- **PC (program counter):** the address of the next instruction.
- **IR (instruction register):** the instruction being executed.
- **MAR (memory address register):** the address being accessed.
- **MDR (memory data register):** the data being read or written.
- **General-purpose registers** R0 to Rn−1.

**Executing Add LOCA, R0** follows these steps:

```flow
PC -> MAR -> Read memory -> MDR -> IR -> Decode -> Fetch operand -> ALU adds -> Result to R0
```

1. Fetch the instruction: PC → MAR, read memory, MDR → IR, and increment the PC.
2. Decode it.
3. Fetch the operand at LOCA through MAR and MDR.
4. Add it to R0 in the ALU.
5. Store the result in R0.

**Interrupts:** a device requests service. The processor saves the PC and status, runs an **interrupt service routine**, then resumes.

### Bus structure

A **bus** is a shared set of lines (data, address and control) connecting the units.

- A **single-bus** structure is simple and cheap, but only one transfer can happen at a time.
- Speeds differ between devices, so **buffer registers** smooth the transfers.
- Multiple-bus designs allow transfers to run in parallel.

### Performance

- **Processor clock:** clock cycles of length P give a clock rate R = 1/P (Hz).
- **Basic performance equation: T = (N × S) / R.**
  - T is the program's execution time.
  - N is the number of instructions executed (the dynamic count).
  - S is the average number of basic steps (clock cycles) per instruction (**CPI**).
  - R is the clock rate.
- **Reducing T:**
  - Reduce N with better compilers or richer instructions.
  - Reduce S with **pipelining** and **superscalar** execution.
  - Increase R with better technology or simpler steps.
- **RISC vs CISC:** RISC uses simple instructions (larger N, smaller S, easy to pipeline). CISC uses complex instructions (smaller N, larger S).
- **Performance measurement:** **SPEC** benchmarks. SPEC rating = (running time on the reference computer) / (running time on the computer under test). Several programs are combined with a **geometric mean**.
- **Compiler role:** an optimising compiler reorders and reduces instructions to lower both N and S.

### Memory locations and addresses

Memory is an array of **words** of n bits each. A k-bit address reaches 2ᵏ locations, so a 24-bit address gives 16M locations.

- **Byte addressability:** each byte has its own address. Word addresses step by 4 for 32-bit words.
- **Big-endian:** the lower byte addresses hold the **more significant** bytes.
- **Little-endian:** the lower byte addresses hold the **less significant** bytes.
- **Word alignment:** a word starts at an address that is a multiple of the word size.
- **Strings:** stored either with their length or with a terminating character.

### Memory operations

- **Load (read):** copy the contents of a memory location into the processor.
- **Store (write):** copy data from the processor into memory, overwriting the location.

Both pass through MAR and MDR.

### Instructions and instruction sequencing

**Register transfer notation:**

- R1 ← [LOC] means R1 gets the contents of LOC.
- R3 ← [R1] + [R2] means R3 gets the sum of the contents of R1 and R2.

**Assembly notation:** for example Move LOC, R1 and Add R1, R2, R3.

**Instruction formats by number of addresses:**

- **Three-address:** Add A, B, C means C ← [A] + [B].
- **Two-address:** Add A, B means B ← [A] + [B].
- **One-address:** uses an **accumulator**. Add A means AC ← [AC] + [A].
- **Zero-address:** stack machines.

**Sequencing and branching:**

- The PC normally increments to the next instruction.
- A **branch** loads a new address into the PC.
- A **conditional branch** tests the **condition-code flags**: **N** (negative), **Z** (zero), **V** (overflow) and **C** (carry).
- **Example: a loop summing n numbers.**
  1. Initialise a counter and a pointer.
  2. In the loop body, add the current number to the sum.
  3. Decrement the counter.
  4. Use Branch>0 to return to the start of the loop.

### Addressing modes

| Mode | Assembler syntax | Effective address (EA) |
|---|---|---|
| Immediate | #Value | Operand = Value (no memory access) |
| Register | Ri | EA = Ri (operand is in the register) |
| Absolute (direct) | LOC | EA = LOC |
| Indirect | (Ri) or (LOC) | EA = [Ri] or [LOC] |
| Index | X(Ri) | EA = X + [Ri] |
| Base with index | (Ri, Rj) | EA = [Ri] + [Rj] |
| Base with index and offset | X(Ri, Rj) | EA = X + [Ri] + [Rj] |
| Relative | X(PC) | EA = X + [PC] |
| Autoincrement | (Ri)+ | EA = [Ri], then increment Ri |
| Autodecrement | −(Ri) | Decrement Ri, then EA = [Ri] |

When to use each:

- **Indirect and index** modes are used for pointers and arrays.
- **Relative** mode is used for branches.
- **Autoincrement and autodecrement** are used for stacks and for walking through lists.

## Module 4 — Input/output organisation and memory

> **In short:** the processor talks to devices by **polling**, **interrupts** (the device asks for attention) or **DMA** (the device copies a whole block to memory by itself). Memory is a **hierarchy**; the **cache** keeps recently used blocks close to the processor.

### Accessing I/O devices

- **Memory-mapped I/O:** device registers share the memory address space, so ordinary Move or Load instructions access them.
- **I/O-mapped I/O:** a separate I/O address space, accessed with special In and Out instructions.

An **I/O interface** contains an address decoder, data and status registers, and control circuits. Status flags, such as SIN (input ready) and SOUT (output ready), tell the processor when it may transfer data.

**Program-controlled I/O** (polling) loops reading a status flag. It is simple but wastes processor time.

### Interrupts

An **interrupt** is a hardware signal (**IRQ**) that tells the processor a device is ready. The processor then:

```flow
Device raises IRQ -> Finish current instruction -> Save PC and status -> Run ISR -> Restore and return
```

1. Finishes the current instruction.
2. Saves the PC and status.
3. Jumps to the **interrupt service routine (ISR)**.
4. Returns with a return-from-interrupt instruction.

Terms to know:

- **Interrupt acknowledge:** the processor's signal to the device that the request has been seen.
- **Interrupt latency:** the delay between the request and the start of the ISR.
- **Interrupt hardware:**
  - In the textbook's (Hamacher's) model, several devices share one **open-drain (open-collector)** request line, which acts as a wired-OR. This is that design's choice, not a rule for every processor.
  - The INTR line is active-low.
- **Enabling and disabling interrupts:** masking is needed so one request doesn't cause endless re-interruption. Methods:
  - The processor ignores INTR until the ISR's first instruction disables interrupts.
  - The processor automatically disables interrupts on entry.
  - **Edge-triggered** inputs.
  - The **interrupt-enable (IE)** bit in the processor status register.
- **Handling multiple devices:**
  - **Identifying the source:** poll each device's IRQ status bit (simple but slow), or use **vectored interrupts**, where the device supplies an **interrupt vector** (the ISR address or code).
  - **Interrupt nesting:** **priority levels**, so a higher-priority device can interrupt a lower-priority ISR.
  - **Simultaneous requests:** resolved by a **daisy chain**. The INTA signal passes from device to device, and the electrically closest device has the highest priority. Priority groups combine the daisy chain with priority levels.
- **Exceptions:** the same mechanism handles exceptions (recovery from errors, debugging traps and single-step mode) and privilege violations.

### Direct memory access (DMA)

For block transfers, a **DMA controller** moves data between a device and memory **without the processor** for each word. The processor programs it with:

- the starting address
- the word count
- the direction (read or write)

The controller raises an interrupt when the block is done. Its registers include the status and control flags (R/W, Done, IE, IRQ).

- **Cycle stealing:** DMA takes the bus for one word at a time, between processor cycles.
- **Block (burst) mode:** DMA keeps the bus for the whole block.

### Bus arbitration

When several masters (processor, DMA controllers) want the bus, only one becomes the **bus master**.

**Centralised arbitration:**

1. A device asserts **Bus Request (BR)**.
2. The arbiter (often the processor) replies with **Bus Grant (BG)**, passed along a daisy chain.
3. The new master asserts **Bus Busy (BBSY)** while it uses the bus.

**Distributed arbitration:**

- Each device places its **ID** on open-collector arbitration lines.
- A device compares the lines with its own ID and drops out on a mismatch.
- The device with the highest ID wins.

### Memory: speed, size and cost

There is a trade-off: fast memory is expensive per bit. This gives a **memory hierarchy**:

| Level | Speed | Size | Cost per bit |
|---|---|---|---|
| Registers | Fastest | Smallest | Highest |
| L1 cache (SRAM, on chip) | | | |
| L2 cache | | | |
| Main memory (DRAM) | | | |
| Secondary storage (magnetic disk, SSD) | Slowest | Largest | Lowest |

The aim is a memory that appears as large as the bottom level and as fast as the top.

### Cache memories

Caches work because of **locality of reference**:

- **Temporal locality:** recently used words are likely to be used again.
- **Spatial locality:** nearby words are likely to be used soon.

Data moves between memory and cache in **blocks** (lines). Terms:

- **Hit:** the requested word is in the cache. **Miss:** it is not, and the block is loaded.
- **Hit rate (h)** and **miss penalty.** In the textbook's form, **t_avg = h·C + (1 − h)·M**, where C is the time to access the cache on a hit and M is the **miss penalty** (the time to bring the block from memory and deliver the word). Example: h = 0.95, C = 1 cycle, M = 20 cycles gives t_avg = 0.95 + 0.05 × 20 = 1.95 cycles. Another common form is AMAT = hit time + miss rate × miss penalty.
- **Write-through:** cache and memory are updated together.
- **Write-back:** memory is updated only when the block is replaced, tracked with a **dirty (modified) bit**.
- **Valid bit:** marks whether a block holds real data.

**Mapping functions.** The textbook example has 64K words of memory in 4096 blocks of 16 words each, and a cache of 128 blocks:

- **Direct mapping:**
  - Memory block j goes to cache block **j mod 128**.
  - Address split: **tag (5) | block (7) | word (4)**.
  - Simple, but two blocks that map to the same line keep evicting each other.
- **Associative mapping:**
  - A block can go **anywhere** in the cache.
  - Address split: **tag (12) | word (4)**.
  - Every tag is compared in parallel, which is flexible but costly.
- **Set-associative mapping:**
  - The cache is divided into sets. A block maps to set **j mod (number of sets)**, and can go in any line within that set.
  - With 2-way sets (64 sets), the address split is **tag (6) | set (6) | word (4)**.
  - It balances the cost of associative mapping with the conflict misses of direct mapping.

**Replacement algorithms:** LRU (least recently used), FIFO or random.

## Module 5 — Basic processing unit and pipelining

> **In short:** inside the processor, every instruction is a sequence of small **register transfers** controlled by signals such as R1out and R4in. **Pipelining** overlaps instructions like an assembly line, so ideally one instruction finishes every clock cycle.

### Some fundamental concepts

To execute an instruction, the processor:

1. **Fetches** it: IR ← [[PC]], then PC ← [PC] + 4.
2. **Decodes** it.
3. Performs the operation, using these basic steps.

**Single-bus organisation:**

- The ALU, the registers (PC, MAR, MDR, IR, R0 to Rn−1, Y, Z and TEMP) and the **instruction decoder** share one internal bus.
- Register **Y** holds one ALU operand.
- Register **Z** holds the ALU result.

### Register transfers

Each register has gating signals: **Riin** loads the register from the bus, and **Riout** places its contents on the bus. To transfer R1 → R4, assert **R1out, R4in**.

### Performing an ALU operation

R3 ← [R1] + [R2] takes three steps:

1. R1out, Yin
2. R2out, SelectY, Add, Zin
3. Zout, R3in

### Fetching a word from memory

Mov (R1), R2 takes four steps:

1. R1out, MARin, Read
2. MDRinE, **WMFC** (wait for memory function completed)
3. MDRout, R2in

The memory responds with an **MFC** signal, which allows for variable memory delay.

### Storing a word in memory

Mov R2, (R1) takes three steps:

1. R1out, MARin
2. R2out, MDRin, Write
3. MDRoutE, WMFC

### Execution of a complete instruction

Add (R3), R1 takes seven steps:

| Step | Action |
|---|---|
| 1 | PCout, MARin, Read, Select4, Add, Zin |
| 2 | Zout, PCin, Yin, WMFC |
| 3 | MDRout, IRin |
| 4 | R3out, MARin, Read |
| 5 | R1out, Yin, WMFC |
| 6 | MDRout, SelectY, Add, Zin |
| 7 | Zout, R1in, End |

Steps 1 to 3 are the **fetch phase**, common to all instructions. **Branch instructions:** PC ← [PC] + offset, computed through the ALU.

Know the control sequences for Add (R3), R1 and for an unconditional branch. They are frequently asked.

### Pipelining: basic concepts

**Pipelining** overlaps the execution of successive instructions, like an assembly line. In a 4-stage pipeline:

```flow
F: Fetch -> D: Decode -> E: Execute -> W: Write
```

- **F** fetches the instruction.
- **D** decodes it and fetches the source operands.
- **E** executes it.
- **W** writes the result.

Each stage takes one clock cycle, and **interstage buffers** hold the intermediate results. Once the pipeline is full, one instruction completes **every cycle**, so k stages give an ideal speedup of up to k.

### Role of cache memory

Each stage must finish in one clock cycle, but main memory is far slower than that. The **cache** (separate instruction and data caches on the chip) is designed so that a **hit** fits in one cycle. A **miss** still stalls the pipeline for the miss penalty. Without caches, the pipeline would stall on every fetch.

### Pipeline performance

**Throughput:** ideally 1 instruction per cycle. **Hazards** cause **stalls** (bubbles):

- **Data hazards:** an instruction needs a result that is not yet written. For example, Add R2, R3, R4 followed by Sub R4, R5, R6 needs R4 too early. Fixes:
  - **Operand forwarding:** send the ALU result straight back to the next instruction.
  - The compiler inserts **NOPs** or **reorders** instructions.
- **Instruction hazards:** the next instruction is not available in time. The textbook (Hamacher) groups two causes here: an **instruction-cache miss** (a memory delay, fixed by better caches and prefetching), and a **branch** (a *control* hazard, as many other books call it, because the fetch address isn't known yet). The **branch penalty** is the wasted cycles. Fixes:
  - An **instruction queue** with prefetching.
  - **Delayed branch** (useful instructions placed in the **branch delay slot**).
  - **Branch prediction**, static or dynamic.
- **Structural hazards:** two instructions need the same hardware at once, such as one memory port. Fixes are separate instruction and data caches, or more ports.

**Performance:**

- Execution time T = (N × S)/R, where S approaches 1 with pipelining.
- Stalls raise the effective S, which reduces the speedup.
- More stages allow a faster clock but bring larger hazard penalties, so a typical design uses a moderate depth.

## Exam tips

- **K-map simplification** with don't-cares, a full-adder or BCD-converter design, and NAND/NOR implementation are near-certain questions. Draw neat maps with the groups marked.
- Write **Verilog** for small circuits (full adder, 4×1 MUX, decoder) in more than one style, and say which style you used.
- Know the **characteristic tables and equations** for SR, D, JK and T flip-flops, and the master–slave D flip-flop diagram.
- **Performance equation**, **addressing modes table**, **big- vs little-endian** and the **control sequence for Add (R3), R1** are standard 6–10 mark answers.
- For **cache mapping**, always draw the address split (tag | block/set | word) with bit counts for the given sizes.
- For **interrupts and DMA**, draw the daisy chain and the bus-arbitration diagram; diagrams carry marks.
