## Module 1 — Introduction, arrays, structures and stacks

> **In short:** a **data structure** is a way to organise data so operations are fast. **Arrays** store items side by side; **structures** group fields; a **stack** is last-in-first-out (push and pop at the top), used for function calls and expression conversion.

### What a data structure is

A **data structure** is a way of organising data in memory so that the operations a program needs — insert, delete, search, traverse, sort — run efficiently. The choice of structure decides the cost of each operation.

- **Primitive** structures are the types the language gives you directly: `int`, `char`, `float`, pointers.
- **Non-primitive** structures are built from them. **Linear** ones keep elements in a sequence (arrays, stacks, queues, linked lists). **Non-linear** ones branch (trees, graphs).

The standard **operations** are traversal, insertion, deletion, searching, sorting and merging.

### Pointers and dynamic memory

A pointer holds an address. `int *p = &x;` makes `p` point to `x`, and `*p` reads or writes `x`.

Memory that must outlive a function, or whose size is known only at run time, comes from the heap:

```c
int *a = malloc(n * sizeof(int));      /* uninitialised block */
int *b = calloc(n, sizeof(int));       /* zero-filled block   */
if (a == NULL || b == NULL) { free(a); free(b); return -1; }

int *t = realloc(a, 2 * n * sizeof(int)); /* grow: use a temporary pointer */
if (t == NULL) { free(a); free(b); return -1; } /* a is still valid here */
a = t;

/* … use a and b … */
free(a);                               /* give each block back once */
free(b);
```

`realloc` returns `NULL` on failure and leaves the old block untouched, so never write `a = realloc(a, …)`: if it fails you lose the only pointer to the old block. Always check the result of every allocation for `NULL`, and `free` every block exactly once. Using a block after `free` (a **dangling pointer**) or never freeing it (a **memory leak**) are the two classic bugs.

### Arrays

An array stores elements of one type in **contiguous** memory, so element `i` is at `base + i × size` and is reached in O(1). For a 2-D array `a[r][c]` stored **row-major** (as C does), the address of `a[i][j]` is `base + (i × c + j) × size`. Insertion or deletion in the middle costs O(n) because elements must shift.

A **dynamically allocated array** is created with `malloc` when the size is known only at run time; a 2-D one is usually an array of row pointers, each row allocated separately.

### Structures and unions

A `struct` groups fields of different types under one name; each field has its own storage. A `union` lets its fields **share** the same storage — only one is valid at a time, and its size is that of the largest field. A **self-referential structure** contains a pointer to its own type, which is how linked lists and trees are built:

```c
struct node { int data; struct node *link; };
```

### Polynomials and sparse matrices

A polynomial is stored as an array of `(coefficient, exponent)` terms in decreasing exponent order. **Addition** walks both term lists like a merge: equal exponents add coefficients, otherwise the larger exponent is copied — O(m + n).

A **sparse matrix** has mostly zeros, so storing it as a full 2-D array wastes space. Store only the non-zero entries as `(row, col, value)` triples, sorted by row then column, with a header triple holding the dimensions and the count. A **fast transpose** first counts the terms in each column, computes where each column starts in the result, then places every term in one pass — O(columns + terms).

### Strings

C strings are `char` arrays ending in `'\0'`. The key library calls are `strlen`, `strcpy`, `strcat` and `strcmp`. **Pattern matching** checks where a pattern occurs in a text; the naive method tries every start position (O(n·m)), and the **KMP** algorithm uses a failure function to avoid re-checking characters (O(n + m)).

### Stacks

A **stack** is a LIFO list: insertion (`push`) and deletion (`pop`) happen at one end, the **top**.

```c
#define MAX 100
int stack[MAX], top = -1;
void push(int x) { if (top == MAX - 1) { puts("overflow");  return; } stack[++top] = x; }
int  pop(void)   { if (top == -1)      { puts("underflow"); return -1; } return stack[top--]; } /* -1 is a simple sentinel: fine for the exam, but it clashes if -1 is a valid item */
```

With a **dynamic array**, a full stack is doubled with `realloc` instead of reporting overflow, so push stays O(1) amortised.

### Evaluating and converting expressions

- **Infix to postfix:** scan left to right. Operands go straight to the output. `(` is pushed. On `)`, pop to the output until `(`. On an operator, pop operators of **higher or equal** precedence (for left-associative operators) to the output, then push it. At the end, pop everything.
- **Evaluating postfix:** push operands; on an operator, pop two values (the first pop is the **right** operand), apply it, push the result. The final value on the stack is the answer.

Example: `A + B * C` → `A B C * +`; with A=2, B=3, C=4 the result is 2 + 12 = 14.

## Module 2 — Queues and singly linked lists

> **In short:** a **queue** is first-in-first-out (insert at the rear, delete at the front); a **circular queue** reuses empty slots. A **linked list** stores items in nodes joined by pointers, so it grows and shrinks without shifting elements.

### Queues

A **queue** is FIFO: insert at the **rear**, delete at the **front**. In a plain array the front keeps moving right, so space at the start is wasted even when the queue is nearly empty.

A **circular queue** fixes this by wrapping indices with `% MAX`:

```c
rear = (rear + 1) % MAX;   /* enqueue position */
front = (front + 1) % MAX; /* dequeue position */
```

One common convention keeps one slot empty: start with `front = rear = 0`; the queue is **empty** when `front == rear` and **full** when `(rear + 1) % MAX == front`, so it holds at most **MAX − 1** items. Enqueue advances `rear` then stores at `rear`; dequeue advances `front` then reads from `front`. A dynamically allocated circular queue doubles its array when full and copies the elements so they stay in order.

### Multiple stacks and queues

Several stacks can share one array: give each a region with its own `boundary[i]` and `top[i]`. When one stack fills, elements of the neighbouring stacks are shifted to make room — useful when total memory is fixed but individual sizes vary.

### Singly linked lists

A linked list stores each element in a **node** holding data and a pointer to the next node; the last node points to `NULL`. Unlike an array it grows one node at a time and inserts or deletes in O(1) once you hold a pointer to the right place, but finding the i-th element is O(n).

```c
struct node { int data; struct node *link; };
struct node *insertFront(struct node *first, int x) {
    struct node *t = malloc(sizeof *t);
    t->data = x; t->link = first;
    return t;                       /* new first node */
}
```

To delete the node after `prev`: `t = prev->link; prev->link = t->link; free(t);`.

### Linked stacks and queues

A **linked stack** pushes and pops at the head — no overflow until memory runs out. A **linked queue** keeps `front` and `rear` pointers: insert after `rear`, delete at `front`.

### Polynomials as linked lists

Each term is a node `(coef, expon, link)` in decreasing exponent order. Adding two polynomials merges the lists in O(m + n), creating a new node for each output term; a zero sum coefficient is dropped. A **circular** list with a header node makes it easy to reuse (erase) a whole polynomial by splicing it onto an available-space list.

## Module 3 — More linked lists, and binary trees

> **In short:** **doubly** and **circular** linked lists make moving in both directions easy. A **binary tree** gives each node at most two children; **traversals** (inorder, preorder, postorder) visit every node in a fixed order.

```flow
Inorder: Left -> Root -> Right
Preorder: Root -> Left -> Right
Postorder: Left -> Right -> Root
```

### Additional list operations

- **Inverting (reversing)** a singly linked list walks it once with three pointers (`lead`, `middle`, `trail`), turning each link around — O(n), no extra nodes.
- **Concatenating** two lists walks to the end of the first and links it to the second.
- On a **circular list** (last node points back to the first) it is convenient to keep a pointer to the **last** node, so both front and rear insertions are O(1).

### Sparse matrices with linked lists

Each non-zero entry becomes a node linked into **both** its row list and its column list (circular lists with header nodes). This makes row-wise and column-wise traversal cheap and lets the matrix grow without a fixed size.

### Doubly linked lists

Each node has `llink` and `rlink` pointers, so the list can be walked both ways and a node can be deleted given only a pointer to itself. With a header node in a circular doubly linked list, insertion after node `p` is:

```c
t->llink = p; t->rlink = p->rlink;
p->rlink->llink = t; p->rlink = t;
```

The cost is one extra pointer per node.

### Trees and binary trees

A **tree** is a finite set of nodes with one **root**; the rest form disjoint subtrees. Terms to know: degree, leaf, parent/child, sibling, level, height (depth).

A **binary tree** has at most two children per node, a left and a right. Key properties:

- Level `i` has at most 2^(i−1) nodes; a tree of depth `k` has at most 2^k − 1 nodes.
- For any non-empty binary tree, **n₀ = n₂ + 1** (leaves = nodes of degree two, plus one).
- A **full** binary tree of depth k has exactly 2^k − 1 nodes; a **complete** tree fills levels left to right.

A complete binary tree fits in an **array**: for node `i`, the parent is at `i/2`, the children at `2i` and `2i+1`. Other trees are usually **linked**: `struct tnode { int data; struct tnode *left, *right; };`.

### Traversals

- **Inorder** (left, root, right) — on a BST this gives sorted order.
- **Preorder** (root, left, right) — gives prefix form of an expression tree.
- **Postorder** (left, right, root) — gives postfix form; used to free a tree.
- **Level order** — visit level by level using a queue.

```c
void inorder(struct tnode *t) {
    if (t) { inorder(t->left); printf("%d ", t->data); inorder(t->right); }
}
```

Iterative inorder uses an explicit stack: push left children until NULL, pop and visit, then move to the right child.

### Threaded binary trees

In a binary tree with n nodes, n + 1 of the 2n link fields are NULL. A **threaded** tree reuses them: a NULL right link points to the node's **inorder successor**, a NULL left link to its **inorder predecessor**. Flag bits (`leftThread`, `rightThread`) mark which links are threads. Inorder traversal then needs **no stack and no recursion**.

## Module 4 — Search trees, forests, disjoint sets and graphs

> **In short:** a **binary search tree** keeps smaller keys on the left and larger on the right, so search follows one path. **Disjoint sets** support union and find. A **graph** is vertices plus edges, stored as an adjacency matrix or list and explored with **BFS** and **DFS**.

### Binary search trees

A **BST** keeps, for every node, smaller keys in the left subtree and larger keys in the right subtree.

- **Search:** compare with the root and go left or right — O(h), where h is the height.
- **Insert:** search for the key; if not found, attach a new node where the search ended.
- **Delete:** a leaf is removed directly; a node with one child is replaced by that child; a node with two children takes the **largest key of its left subtree** (or smallest of its right), and that node is deleted instead.

h is O(log n) for a balanced tree but O(n) in the worst case (keys inserted in sorted order).

### Selection (tournament) trees

To merge k sorted runs, a **winner tree** keeps the k current front elements in the leaves; each internal node holds the smaller of its children, so the root is the overall minimum. After outputting it, only the path from that leaf to the root is replayed — O(log k) per element. A **loser tree** stores the loser at each internal node, which makes replay slightly simpler.

### Forests

A **forest** is a set of disjoint trees. It converts to one binary tree by the **left-child, right-sibling** rule: each node's first child becomes its left child and its next sibling becomes its right child; the roots of the trees are chained as right siblings.

### Disjoint sets (union–find)

Each set is a tree stored in a `parent[]` array, with the root marking the set.

- **Find(i):** follow parents to the root. **Collapsing** (path compression) then points every node on that path straight to the root.
- **Union(i, j):** make one root the child of the other. **Weighting rule:** attach the tree with fewer nodes under the larger (store `−count` in the root). With both rules, a sequence of operations runs in nearly linear time.

### Counting binary trees

The number of distinct binary trees with n nodes is the **Catalan number** C(2n, n)/(n + 1): 1, 2, 5, 14, 42… for n = 1, 2, 3, 4, 5. The same number counts the different stack permutations of 1…n and the ways to parenthesise a product.

### Graphs

A **graph** G = (V, E) is a set of vertices and edges; edges are **undirected** (u, v) or **directed** ⟨u, v⟩. Terms: adjacent, degree (in-/out-degree), path, cycle, connected, connected component, complete graph (n(n−1)/2 edges undirected).

Representations:

- **Adjacency matrix** — n × n, `a[i][j] = 1` if an edge exists. O(n²) space; edge test O(1).
- **Adjacency lists** — one linked list of neighbours per vertex. O(n + e) space; best for sparse graphs.
- **Adjacency multilists** — one node per edge shared by both endpoints' lists (undirected graphs).

Elementary operations:

- **Depth-first search (DFS)** visits a vertex, then recursively visits each unvisited neighbour (uses a stack/recursion).
- **Breadth-first search (BFS)** visits all neighbours of a vertex before going deeper (uses a queue).
- Both run in O(n + e) on adjacency lists (O(n²) on a matrix) and find **connected components** and **spanning trees**.

## Module 5 — Hashing, priority queues and optimal BSTs

> **In short:** **hashing** maps a key straight to a table slot, so search is about O(1); **collisions** are handled by chaining or open addressing. A **priority queue** (heap) always gives the highest-priority item first.

### Hashing

Hashing stores a key at an address computed from the key, aiming for O(1) search. A **hash function** maps a key to a bucket; a good one is fast and spreads keys evenly. Common functions: **division** (`k mod M`, M usually prime), **mid-square**, **folding**, and **digit analysis**.

Two keys mapping to the same bucket is a **collision**. Handling it in **static hashing** (fixed table size):

- **Open addressing / linear probing:** try the next slots `(h + i) mod M`. Simple, but keys cluster.
- **Quadratic probing** and **rehashing** (a second hash function) reduce clustering.
- **Chaining:** each bucket holds a linked list of all keys that hash there.

The **load factor** α = n / M (keys ÷ buckets) decides performance; as it rises, probes get longer.

**Dynamic hashing** lets the table grow without rehashing everything. **Extendible hashing** uses a **directory** indexed by the first few bits of the hash; when a bucket overflows only that bucket splits, and the directory doubles only if needed.

### Priority queues

A **priority queue** always removes the element with the highest (or lowest) priority. The usual implementation is a **heap** — a complete binary tree in an array where each parent is ≥ its children (max-heap). Insert adds at the end and sifts up; delete removes the root, moves the last element to the root and sifts down — both O(log n).

A **double-ended priority queue** supports deleting both the minimum and the maximum (implemented with structures such as min-max heaps).

### Leftist trees

A **leftist tree** is a binary tree where, at every node, the **shortest path to an external node** (`shortest(left) ≥ shortest(right)`) is on the right. This keeps the right path short (O(log n)), so two leftist heaps **meld (merge)** by merging their right paths and swapping children where needed — O(log n). Insert and delete-min are both done with a meld.

### Optimal binary search trees

When keys are searched with known, unequal probabilities, the best BST is not necessarily balanced: frequently searched keys should be near the root. An **optimal BST** minimises the expected search cost Σ p(i)·level(aᵢ) + Σ q(i)·(level(Eᵢ) − 1), where p are successful-search and q unsuccessful-search probabilities.

It is built by **dynamic programming**. Take keys a₁ < a₂ < … < aₙ, success probabilities p(1…n) and failure probabilities q(0…n). Using the textbook's convention, **Tᵢⱼ is the optimal tree for the keys aᵢ₊₁ … aⱼ** (so it holds j − i keys, and Tᵢᵢ is empty):

- w(i, i) = q(i), and w(i, j) = w(i, j−1) + p(j) + q(j)
- c(i, i) = 0, and **c(i, j) = w(i, j) + min over i < k ≤ j of [c(i, k−1) + c(k, j)]**
- r(i, j) = the k that gives the minimum (the root of Tᵢⱼ)

The root aₖ is excluded from both subtrees automatically: the left subtree Tᵢ,ₖ₋₁ holds aᵢ₊₁ … aₖ₋₁ and the right subtree Tₖⱼ holds aₖ₊₁ … aⱼ. (Books that index a range as "keys i … j" write the same idea as C(i, j) = min over i ≤ k ≤ j of [C(i, k−1) + C(k+1, j)] + Σ p; don't mix the two conventions.) The answer is c(0, n), and the tree is rebuilt from the r table. Solving ranges in order of increasing size gives the optimal tree in O(n³) (O(n²) with Knuth's speed-up).
