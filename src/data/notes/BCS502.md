## Module 1 — Introduction, network models and the physical layer

> **In short:** a network moves data from one device to another. The work is split into **layers**; each layer does one job and adds its own header. The physical layer turns bits into signals on a cable or radio wave.

### Data communications

**Data communication** is the exchange of data between two devices over a transmission medium. Its quality depends on four characteristics:

- **Delivery**: the data reaches the correct destination.
- **Accuracy**: the data arrives without alteration.
- **Timeliness**: the data arrives in time to be useful (essential for audio and video).
- **Jitter**: the variation in packet arrival time is kept small.

A data-communication system has five components: **message**, **sender**, **receiver**, **transmission medium** and **protocol**.

Data flow can be **simplex** (one direction only, such as a keyboard), **half-duplex** (both directions, one at a time, such as walkie-talkies) or **full-duplex** (both directions at once, such as a telephone).

### Networks and network types

A **network** is a set of devices (nodes) connected by communication links.

- **Criteria:** performance (throughput and delay), reliability and security.
- **Connection types:** **point-to-point** (a dedicated link between two devices) or **multipoint** (one link shared by many).
- **Physical topologies:**
  - **Mesh:** n(n−1)/2 links; robust but costly.
  - **Star:** a central hub; easy to install, but the hub is a single point of failure.
  - **Bus:** one backbone cable; cheap, but a break in it stops the network.
  - **Ring:** each device connects to two neighbours; a break can disable the ring.
- **By scope:**
  - **LAN:** a building or campus.
  - **WAN:** a wide area. A **point-to-point WAN** joins two devices; a **switched WAN** joins many.
  - **Internetwork:** two or more networks connected. The **Internet** is the largest.
- **Switching:**
  - **Circuit-switched:** a dedicated path for the whole call (the telephone network).
  - **Packet-switched:** data is sent as independent packets through routers.

### Protocol layering

A **protocol** defines the rules both sides follow. Layering splits a complex task into smaller tasks, each handled by its own layer:

- Each layer uses the services of the layer below and serves the layer above.
- Two principles apply. Each layer must be **bidirectional** (it does a task and its inverse). The objects under a layer must be **identical** at both ends.
- **Logical connections** run between peer layers.

### The TCP/IP protocol suite

TCP/IP has five layers:

| Layer | Unit of data | Addressing | Main job |
|---|---|---|---|
| Application | Message | Names (URLs, emails) | Services to the user (HTTP, SMTP, DNS) |
| Transport | Segment / user datagram | Port numbers | Process-to-process delivery (TCP, UDP) |
| Network | Datagram | IP (logical) addresses | Host-to-host delivery and routing (IP) |
| Data link | Frame | MAC (link) addresses | Node-to-node delivery over one link |
| Physical | Bits | — | Sending bits as signals over the medium |

**Encapsulation:** each layer adds its header on the way down. **Decapsulation** removes it on the way up. A **router** works up to the network layer; a **link-layer switch** works up to the data link layer.

```flow
Message (Application) -> Segment (Transport) -> Datagram (Network) -> Frame (Data link) -> Bits (Physical)
```

### The OSI model

The ISO **OSI model** has seven layers: physical, data link, network, transport, **session**, **presentation** and application.

- **Session layer:** dialog control and synchronisation.
- **Presentation layer:** translation, encryption and compression.
- **Why TCP/IP won:** it was already widely deployed, and OSI's session and presentation layers were never fully specified. OSI remains the standard teaching model.

### Transmission media

**Guided media** carry the signal along a physical path:

- **Twisted-pair cable:** twisting cancels noise. Comes as **UTP** and **STP**, and is used in telephone lines and Ethernet (Cat 5e, Cat 6).
- **Coaxial cable:** a central conductor inside a shield, used in cable TV.
- **Fibre-optic cable:** light carried by **total internal reflection**.
  - Modes: **multimode step-index**, **multimode graded-index** and **single-mode**.
  - Advantages: high bandwidth, low attenuation, immunity to electromagnetic interference, and light weight.

**Unguided (wireless) media:**

- **Radio waves** (3 kHz–1 GHz): omnidirectional; used in AM/FM radio.
- **Microwaves** (1–300 GHz): unidirectional, line-of-sight; used in cellular, satellite and wireless LANs.
- **Infrared** (300 GHz–400 THz): short range, cannot pass through walls; used in remote controls.

### Switching: packet switching and its types

- **Datagram networks:** each packet is routed independently and packets may arrive out of order. There is no setup phase. The Internet's network layer works this way.
- **Virtual-circuit networks:** have a setup phase, a data-transfer phase and a teardown phase. All packets follow the same path and carry a **virtual-circuit identifier (VCI)** that changes at each switch. ATM and Frame Relay work this way.
- **Delay comparison:** circuit switching adds a setup delay but no per-packet routing delay. Datagram switching adds routing work and queueing at every router.

## Module 2 — Data link layer

> **In short:** the data link layer moves a **frame** across **one link**. It finds errors (parity, CRC, checksum), makes frames (flags and stuffing), and decides **who may send** when many devices share the same wire (ALOHA, CSMA/CD, CSMA/CA).

### Error detection and correction

- **Types of error:**
  - A **single-bit error** changes one bit.
  - A **burst error** changes two or more bits; its length is counted from the first corrupted bit to the last.
- **Redundancy:** extra bits are added so the receiver can detect or correct errors.
- **Detection versus correction:** detection only tells you an error happened. Correction must also find which bits are wrong.

### Block coding

The message is split into **k-bit datawords**, and each is turned into an **n-bit codeword** (r = n − k redundant bits).

- **Hamming distance** d(x, y) is the number of positions in which two words differ. The **minimum Hamming distance** d_min is the smallest distance between any two valid codewords.
- To **detect** up to s errors, you need d_min = s + 1.
- To **correct** up to t errors, you need d_min = 2t + 1.
- A **simple parity-check code** (n = k + 1) adds one parity bit so the number of 1s is even. It detects any odd number of errors.
- In a **linear block code**, the XOR of two valid codewords is another valid codeword.

### Cyclic codes and CRC

In a cyclic code, rotating a codeword gives another codeword. **CRC (cyclic redundancy check)** works as follows:

```flow
Dataword + r zeros -> Divide by generator (XOR) -> Remainder = CRC -> Send dataword + CRC
Receiver divides again -> Remainder 0 = accept -> Non-zero = discard
```

1. Represent data and divisor as polynomials. The divisor (**generator**) g(x) has degree r.
2. Append r zeros to the dataword and divide by the generator using **modulo-2 division** (XOR, no carries).
3. The r-bit **remainder** is the CRC. Replace the appended zeros with it to form the codeword.
4. The receiver divides the received codeword by the same generator. A zero **syndrome** means no error was detected; a nonzero syndrome means there is an error.

**Worked example (practise this):** dataword 1001, generator 1011 (x³ + x + 1). Divide 1001000 by 1011 and the remainder is 110, so the codeword is 1001110.

A good generator has at least two terms and its x⁰ coefficient is 1. Then it detects all burst errors of length ≤ r, which is why CRC is used in Ethernet and HDLC.

### Checksum

The **Internet checksum** is computed like this:

1. Split the data into 16-bit words.
2. Add them using **one's-complement** arithmetic, wrapping any carry back into the sum.
3. Complement the result.

The receiver adds all the words including the checksum. If the complement of the result is 0, the data is accepted. The checksum is weaker than CRC but cheap in software. Where it is used:

- **IPv4:** a checksum over the IPv4 header only (recomputed at each router, because TTL changes).
- **IPv6:** no header checksum at all.
- **TCP and UDP:** a checksum over a pseudo-header (addresses, protocol, length), the header and the data. It is mandatory for TCP. For UDP it is optional over IPv4 and required over IPv6.

### Data link control (DLC) services

**Framing** splits the bit stream into frames:

- **Fixed-size framing:** no delimiters are needed (as in ATM cells).
- **Variable-size framing:** comes in two kinds.
  - **Character-oriented:** a flag byte marks the frame, and **byte stuffing** inserts an ESC byte before any flag or ESC byte that appears in the data.
  - **Bit-oriented:** the flag is 01111110, and **bit stuffing** inserts a 0 after every five consecutive 1s in the data.

**Flow control** stops a fast sender from overwhelming a slow receiver, using buffers and feedback. **Error control** detects lost or corrupted frames and retransmits them, using ACKs, sequence numbers and timers.

A DLC can also be **connectionless** (frames are independent) or **connection-oriented** (frames are numbered, with a setup phase and a teardown phase).

### Data link layer protocols

- **Simple protocol:** no flow or error control, for an ideal noiseless channel.
- **Stop-and-Wait protocol:**
  - The sender sends one frame, starts a timer and waits for an ACK.
  - Frames and ACKs carry 1-bit sequence numbers (0, 1) so duplicates can be detected.
  - It is simple but inefficient when the **bandwidth–delay product** is large.
  - **Efficiency** = 1 / (1 + 2a), where a = propagation time / frame transmission time. This assumes an error-free channel and ignores ACK transmission time, headers and processing delay.
  - Example: 1000-bit frames at 1 Mbps take 1 ms to send; with 10 ms propagation, a = 10, so efficiency = 1/21 ≈ 4.8%.
- **Go-Back-N** and **Selective Repeat** pipeline many frames inside a sliding window. These are covered with TCP in Module 4.

### HDLC (High-level Data Link Control)

HDLC is a bit-oriented protocol.

- **Configurations:**
  - **Normal response mode:** one primary station and several secondaries.
  - **Asynchronous balanced mode:** peer stations.
- **Frame types:**
  - **I-frames (information):** carry user data, plus piggybacked ACKs.
  - **S-frames (supervisory):** carry flow and error control (RR, RNR, REJ, SREJ).
  - **U-frames (unnumbered):** carry link management.
- **Frame fields:** Flag | Address | Control | Information | FCS | Flag.

### Point-to-Point Protocol (PPP)

PPP is a **byte-oriented** protocol for point-to-point links, such as dial-up and DSL.

- **Services:** framing, a **Link Control Protocol (LCP)** to set up the link, authentication with **PAP** or **CHAP**, and **Network Control Protocols** (such as IPCP) to carry network-layer data.
- **What PPP does not provide:** flow control, and full error control (it only detects errors and discards bad frames).
- **Transition phases:** dead → establish → authenticate → network → open → terminate.

### Media access control (MAC)

When many stations share one medium, a **multiple-access protocol** decides who sends.

**Random access** (no station is in charge):

- **ALOHA:**
  - **Pure ALOHA:** stations send whenever they have data, and a collision means retransmitting after a random backoff. Vulnerable time is 2 × T_fr, and maximum throughput is S = G·e^(−2G) = **18.4%** at G = 0.5.
  - **Slotted ALOHA:** stations send only at slot starts. Vulnerable time is T_fr, and maximum throughput is S = G·e^(−G) = **36.8%** at G = 1.
- **CSMA (carrier sense multiple access):** a station senses the medium before sending. Collisions still happen because of propagation delay. Persistence methods:
  - **1-persistent:** if the channel is idle, send immediately.
  - **Non-persistent:** if the channel is busy, wait a random time before sensing again.
  - **p-persistent:** in slotted channels, send with probability p.
- **CSMA/CD (collision detection):** a station keeps sensing while it sends and aborts on a collision, sending a jam signal and then backing off. Exponential backoff picks a random K in [0, 2ⁿ − 1]. The minimum frame time must be at least 2 × propagation time. This is classic Ethernet.

```flow
Sense channel -> Idle? Send frame -> Collision? Send jam signal -> Back off random time -> Try again
```
- **CSMA/CA (collision avoidance):** used in wireless networks, where collisions cannot be detected. It uses an **IFS** gap, a **contention window** and **acknowledgements**, and optionally **RTS/CTS** and the **NAV**.

**Controlled access** (stations take turns):

- **Reservation:** a station reserves a slot in a reservation frame.
- **Polling:** a primary station sends a **poll** (asking a secondary to send) or a **select** (telling a secondary to receive).
- **Token passing:** a token circulates in a logical ring. Only the holder may send.

## Module 3 — Network layer

> **In short:** the network layer delivers a packet from the **source host to the destination host**, across many networks. Every host gets an **IP address**; routers use **routing protocols** (RIP, OSPF, BGP) to build tables and **forward** each packet one hop closer.

### Network-layer services

- **Packetising:** encapsulating transport data into datagrams at the source and decapsulating them at the destination.
- **Routing:** finding the best route, done by routing protocols.
- **Forwarding:** at each router, deciding the output interface for a packet from its forwarding table.
- **Other services:** error control (only a header checksum in IPv4), flow control (none), congestion control, quality of service and security.

### Packet switching at the network layer

- **Datagram approach (connectionless):** each packet is forwarded by its destination address. This is the Internet's approach.
- **Virtual-circuit approach (connection-oriented):** packets carry a flow label and are forwarded by that label after a setup phase. MPLS uses the same idea: packets get a short **label** and follow a pre-set **label-switched path** through the network.

### IPv4 addresses

An IPv4 address is **32 bits**, written in dotted-decimal (192.168.1.10). The address space is 2³² ≈ 4.3 billion addresses.

- **Classful addressing** (now obsolete):

  | Class | First bits | Default mask | Notes |
  |---|---|---|---|
  | A | 0 | /8 | 126 usable networks |
  | B | 10 | /16 | |
  | C | 110 | /24 | |
  | D | 1110 | — | Multicast |
  | E | 1111 | — | Reserved |

  It wasted addresses, which led to **CIDR**.
- **Classless addressing (CIDR):** an address is written a.b.c.d/n, where n is the **prefix length**.
  - The **network (first) address** is the address with the last 32 − n bits set to 0.
  - The **last (broadcast) address** has those bits set to 1.
  - The **number of addresses** is 2^(32−n).
- **Worked example:** 167.199.170.82/27.
  - The mask keeps the first 27 bits, giving a block of 32 addresses.
  - First address 167.199.170.64; last address 167.199.170.95.
- **Subnetting:** a block is split into smaller blocks, and each subnet's size must be a power of 2.
- **Special addresses:**
  - 0.0.0.0 means "this host, no address yet". A host uses it as a source address while it asks DHCP for an address. (In server software, binding to 0.0.0.0 means "listen on all local interfaces".)
  - 255.255.255.255 is limited broadcast.
  - 127.0.0.0/8 is loopback.
  - **Private blocks** are 10/8, 172.16/12 and 192.168/16.
- **DHCP** assigns addresses automatically.
- **NAT** lets many private hosts share one public address.

### The IPv4 datagram

The header is 20–60 bytes:

- **VER** (4), **HLEN** (header length in 4-byte words)
- **Service type** (DiffServ)
- **Total length** (at most 65,535)
- **Identification, flags (D = do not fragment, M = more fragments) and fragmentation offset** (in 8-byte units)
- **TTL** (decremented at each router; the packet is dropped at 0)
- **Protocol** (TCP = 6, UDP = 17, ICMP = 1)
- **Header checksum**
- **Source and destination addresses**
- **Options**

**Fragmentation** splits a datagram to fit the link's **MTU**. Only the destination reassembles it, using the identification, flags and offset fields.

### IPv6 datagram

IPv6 has **128-bit addresses**, written as eight groups of hex separated by colons. Leading zeros can be dropped, and :: replaces one run of zero groups.

- **Base header:** a fixed **40 bytes**. Fields are version, traffic class, **flow label**, payload length, **next header**, **hop limit**, and source and destination addresses.
- **Changes from IPv4:**
  - No header checksum.
  - Routers do not fragment; only the source does, after path-MTU discovery.
  - Options move into **extension headers**.
  - Built-in support for security (IPsec) and quality of service.
- **Transition from IPv4:** dual stack, **tunnelling** and **header translation**.

### Routing algorithms

The internet is modelled as a **graph**: routers are nodes, and links are weighted edges (costs). A **least-cost tree** is built for every router.

- **Distance-vector routing (DVR):**
  - Each router keeps a vector of least costs to every destination and shares it **only with neighbours**, periodically or when it changes.
  - Each router updates with the **Bellman-Ford** equation: D_x(y) = min over neighbours v of { c(x, v) + D_v(y) }.
  - Problem: **count to infinity** (slow convergence after a link failure). Fixes are **split horizon**, **poison reverse** and a finite "infinity" (16 in RIP).
- **Link-state routing (LSR):**
  - Each router floods **link-state packets (LSPs)** describing its links to **every** router, so all routers hold the same **link-state database**.
  - Each router runs **Dijkstra's algorithm** to build its own least-cost tree.
- **Path-vector routing (PVR):**
  - Routers advertise the whole **path** to a destination, not just its cost.
  - A route whose path already contains the receiver is rejected (loop prevention).
  - Routes are chosen by **policy**, not just cost. BGP uses it.

### Unicast routing protocols

The Internet is divided into **autonomous systems (ASes)**:

```flow
Inside one AS (intra-domain) -> RIP (distance vector) or OSPF (link state)
Between ASes (inter-domain) -> BGP (path vector)
```

- **Intra-domain routing** happens inside an AS (RIP, OSPF).
- **Inter-domain routing** happens between ASes (BGP).

The protocols:

- **RIP (Routing Information Protocol):**
  - **Distance vector**; the metric is the **hop count** (maximum 15, with 16 meaning infinity).
  - Updates every 30 s.
  - Runs over **UDP port 520**.
  - Suited to small networks.
- **OSPF (Open Shortest Path First):**
  - **Link state.** Metric costs are set by the administrator.
  - Divides an AS into **areas** joined by a **backbone area (area 0)**.
  - Message types: hello, database description, link-state request, update and acknowledgement.
  - Runs directly over IP.
  - Converges fast and scales to large ASes.
- **BGP (Border Gateway Protocol), version 4:**
  - **Path vector**, used between ASes.
  - **eBGP** runs between ASes; **iBGP** runs inside one.
  - Runs over **TCP port 179**.
  - Path attributes such as AS-PATH and NEXT-HOP support **policy routing**.

### Multicast routing: MOSPF

Multicasting sends one packet to a **group** of receivers. **MOSPF (Multicast OSPF)** extends OSPF:

- Routers learn group membership through **IGMP** and flood this as a group-membership link-state advertisement.
- Each router builds a **source-based shortest-path tree** for each (source, group) pair, using Dijkstra's algorithm.
- The tree is built **on demand** when the first packet of a flow arrives.

## Module 4 — Transport layer

> **In short:** the transport layer delivers data from **one program to another** (process to process) using **port numbers**. **UDP** is fast and simple with no guarantees. **TCP** sets up a connection and makes delivery reliable, in order, and polite to the network (flow and congestion control).

### Transport-layer services

The transport layer provides **process-to-process** (end-to-end) delivery:

- **Addressing** uses **port numbers** (16 bits):
  - Well-known ports: 0–1023.
  - Registered ports: 1024–49,151.
  - Dynamic ports: 49,152–65,535.
  - A **socket address** is an IP address plus a port.
- **Encapsulation, multiplexing and demultiplexing:** many processes share one network layer.
- **Further services:** flow control, error control and congestion control.
- **Connection model:** connectionless (UDP) or connection-oriented (TCP).

### Transport-layer protocols (the general ones)

- **Simple protocol:** connectionless, with no flow or error control.
- **Stop-and-Wait:**
  - Send window = 1. Sequence numbers are modulo 2.
  - A timer triggers retransmission.
- **Go-Back-N (GBN):**
  - Send window up to 2^m − 1, receive window = 1.
  - **Cumulative ACKs.**
  - On a timeout, the sender resends **all** outstanding packets.
- **Selective Repeat (SR):**
  - Send and receive windows are each at most 2^(m−1).
  - The receiver buffers out-of-order packets.
  - Only the lost packet is resent.
- **Piggybacking:** in two-way communication, ACKs ride on data packets.
- **Why the window limits:** larger windows would let a receiver mistake a new packet for an old one after its ACKs are lost.

### User Datagram Protocol (UDP)

UDP is **connectionless and unreliable**, with an **8-byte header**: source port, destination port, length and checksum.

- **Checksum:** covers a **pseudo-header** (IP addresses, protocol, length) plus the UDP header and data. It is optional in IPv4.
- **Missing features:** no flow control, no error control apart from the checksum, and no congestion control.
- **Uses:** simple request–response (DNS), multicasting, real-time media (VoIP, streaming), and management (SNMP).

### Transmission Control Protocol (TCP)

**Services:**

- **Process-to-process** communication.
- **Stream delivery** with send and receive buffers.
- **Full-duplex** and **connection-oriented**.
- **Reliable**: delivery is in order with no loss or duplication.

**Features:** byte **numbering** (sequence and acknowledgement numbers count bytes), flow control, error control and congestion control.

**Segment format** (20–60-byte header):

- Source port, destination port
- **Sequence number** (number of the first data byte)
- **Acknowledgement number** (next byte expected)
- **HLEN**
- **Control flags:** URG, ACK, PSH, RST, SYN, FIN
- **Window size** (receiver window, rwnd)
- Checksum, urgent pointer, options

**TCP connection:**

```flow
Client: SYN (seq = x) -> Server: SYN + ACK (seq = y, ack = x + 1) -> Client: ACK (ack = y + 1) -> Connection open
```

- **Establishment, the three-way handshake:**
  1. The client sends **SYN** (seq = x).
  2. The server replies **SYN + ACK** (seq = y, ack = x + 1).
  3. The client sends **ACK** (ack = y + 1).

  A **SYN flooding attack** exploits half-open connections. **SYN cookies** are a defence.
- **Data transfer:** pushing (PSH), and urgent data (URG).
- **Termination:** a three-way handshake (FIN, FIN + ACK, ACK) or a four-way one with a **half-close**. The side that closes first waits in **TIME-WAIT** for 2 MSL.
- **Reset:** RST aborts a connection.
- **State diagram:**
  - Main states: CLOSED, LISTEN, SYN-SENT, SYN-RCVD, ESTABLISHED, FIN-WAIT-1/2, CLOSE-WAIT, LAST-ACK and TIME-WAIT.
  - Learn the client path (active open, active close) and the server path (passive open, passive close).

**Flow control:**

- The receiver advertises **rwnd** (free buffer space). The sender's window = min(rwnd, cwnd).
- The window **opens**, **closes** and **shrinks** as data is acknowledged and the buffer fills.
- **Silly window syndrome** has two fixes: **Nagle's algorithm** at the sender, and **Clark's solution** or delayed ACKs at the receiver.

**Error control:**

- Uses the **checksum**, **cumulative ACKs** (and selective ACKs as an option) and **retransmission**.
- **Retransmission** happens on an **RTO timeout** or on **three duplicate ACKs** (fast retransmit).
- **RTO calculation:**
  - RTT_S = (1 − α)·RTT_S + α·RTT_M
  - RTT_D = (1 − β)·RTT_D + β·|RTT_S − RTT_M|
  - RTO = RTT_S + 4·RTT_D
- **Karn's algorithm:** don't update the RTT from retransmitted segments.

**Congestion control:**

```flow
Slow start (cwnd doubles each RTT) -> Reaches ssthresh -> Congestion avoidance (cwnd + 1 per RTT)
Timeout -> ssthresh = cwnd / 2, cwnd = 1 -> Slow start again
3 duplicate ACKs (Reno) -> Fast recovery -> Congestion avoidance
```

- The **congestion window (cwnd)** limits the sender.
- **Slow start:** cwnd starts at 1 MSS and doubles each RTT (exponential growth) until it reaches the threshold **ssthresh**.
- **Congestion avoidance:** above ssthresh, cwnd grows by 1 MSS per RTT (additive increase).
- **On a timeout:** ssthresh = cwnd / 2 and cwnd = 1, then slow start begins again. This is **Taho TCP**.
- **On three duplicate ACKs:** **Reno TCP** uses **fast recovery**: ssthresh = cwnd / 2, cwnd = ssthresh + 3, then congestion avoidance.
- **The overall pattern:** **AIMD** (additive increase, multiplicative decrease) gives TCP's sawtooth pattern. **Throughput** ≈ (0.75 × W_max) / RTT.

## Module 5 — Application layer

> **In short:** the application layer is what the user sees: the web (**HTTP**), file transfer (**FTP**), email (**SMTP**, **POP3**, **IMAP**), names to addresses (**DNS**) and remote login (**TELNET**, **SSH**). Learn each one's job, port number and message flow.

### Introduction and client–server programming

Application-layer programs provide services to the user. There are two paradigms:

- **Client–server:** a server runs continuously, waiting for requests. Clients start the communication.
- **Peer-to-peer:** peers are both client and server, as in BitTorrent.

**Socket interface:**

- The **socket** is the endpoint an application uses to talk to the transport layer.
- **Server-side calls:** socket(), bind(), listen(), accept(), then read() and write().
- **Client-side calls:** socket(), connect(), then write() and read().
- **Server types:** an **iterative server** handles one client at a time (common with UDP). A **concurrent server** creates a child process or thread for each client (common with TCP).

### World Wide Web and HTTP

- The **web** is a distributed client–server service. A **browser** fetches **web pages** identified by a **URL**: protocol://host:port/path.
- **Web documents** are **static**, **dynamic** (generated by the server, as with CGI, PHP or JSP) or **active** (code run in the browser, such as JavaScript).
- **HTTP** runs over **TCP port 80** (HTTPS uses port 443). This is the HTTP/1.1 model in the textbook; the newer HTTP/3 runs over QUIC on UDP port 443.
  - **Connections:**
    - A **nonpersistent** connection uses one TCP connection per object.
    - A **persistent** connection is reused for many objects (the default in HTTP/1.1).
    - Know the RTT calculation for each.
  - **Request message:** request line (**method**, URL, version), header lines, blank line, body. The methods are GET, HEAD, POST, PUT, DELETE, CONNECT and OPTIONS.
  - **Response message:** status line (version, **status code**, phrase), headers, body. The code families:
    - 1xx informational
    - 2xx success (200 OK)
    - 3xx redirection (301 Moved Permanently)
    - 4xx client error (404 Not Found)
    - 5xx server error
  - **Cookies:** HTTP is stateless. Cookies (Set-Cookie and Cookie headers) let a server remember a client, for shopping carts, logins and ads.
  - **Web caching (proxy servers):** a proxy keeps copies of responses to reduce delay and traffic. Conditional GET (If-Modified-Since) keeps them fresh.

### FTP (File Transfer Protocol)

FTP uses **two TCP connections**:

- A **control connection** on **port 21**, persistent for the whole session; commands and responses travel as ASCII text.
- A **data connection**, opened for each file transfer. In **active mode** the server connects from **port 20** to the client; in **passive mode** (common behind firewalls) the client connects to a port the server announces.
- **Main commands:** USER, PASS, LIST, RETR, STOR, QUIT.
- **Response codes:** three digits (for example 220 service ready, 226 transfer complete).
- **File types:** ASCII and binary. **Transmission modes:** stream, block and compressed.
- **Security:** FTP sends passwords in plain text, so SFTP or FTPS is used instead.

### Electronic mail

Mail uses three components:

```flow
Sender's user agent -> SMTP -> Sender's mail server -> SMTP -> Receiver's mail server -> POP3 / IMAP -> Receiver's user agent
```

- **User agent (UA):** composes, reads and handles mail.
- **Message transfer agent (MTA):** pushes mail between servers using **SMTP** on **TCP port 25**. (Mail programs usually *submit* outgoing mail to their own server on port 587 or 465, with encryption.) SMTP commands include HELO, MAIL FROM, RCPT TO, DATA and QUIT. A message is transferred in three phases: connection establishment, mail transfer and connection termination.
- **Message access agent (MAA):** pulls mail from the mailbox using **POP3** (port 110; downloads mail, with delete or keep modes) or **IMAP4** (port 143; mail stays on the server, with folders and partial download).

Other mail standards:

- **MIME:** lets mail carry non-ASCII data (images, audio) by adding headers such as Content-Type and Content-Transfer-Encoding (base64).
- **Web-based mail:** HTTP is used between the browser and the mail server.

### Domain Name System (DNS)

DNS maps **names to IP addresses**. It is a distributed, hierarchical database.

- **Name space:** an inverted tree with up to 128 levels. Labels are joined into a **fully qualified domain name** (FQDN).
- **Zones** are served by **primary** and **secondary** servers, under **root servers** at the top.
- **Domains:**
  - **Generic domains:** com, org, edu and others.
  - **Country domains:** in, uk and others.
- **Resolution:** **recursive** (the server does the whole lookup) or **iterative** (the server refers the client to the next server). Answers are **cached** with a TTL.
- **Resource records:**
  - A: IPv4 address
  - AAAA: IPv6 address
  - NS: name server
  - CNAME: alias
  - MX: mail exchanger
  - PTR: reverse lookup
  - SOA: start of authority
- **Transport:** **UDP port 53** for queries, and TCP for zone transfers or large responses.
- **Security:** threats include cache poisoning; **DNSSEC** adds signatures.

### TELNET

**TELNET** (TErminaL NETwork) gives **remote login** over **TCP port 23**.

- It uses the **Network Virtual Terminal (NVT)** character set so different systems can communicate.
- Control commands are sent in-band, prefixed by **IAC**. Options (such as echo) are negotiated with WILL, WONT, DO and DONT.
- **Security:** everything, including passwords, travels unencrypted, which is why SSH replaced it.

### Secure Shell (SSH)

**SSH** provides secure remote login and file transfer over **TCP port 22**. It has three layers:

- **SSH-TRANS (transport layer protocol):** negotiates algorithms, exchanges keys (Diffie–Hellman), authenticates the server and gives a confidential, integrity-protected channel.
- **SSH-AUTH:** authenticates the client with a password or a public key.
- **SSH-CONN:** multiplexes many logical channels (shell, port forwarding) over one connection.

Applications include remote login, SFTP and SCP file transfer, and **port forwarding** (tunnelling).

## Exam tips

- **CRC, checksum and Hamming distance** problems appear almost every year. Show the full division or addition.
- For IPv4, practise finding the **first address, last address and number of addresses** from a CIDR block, and dividing a block into subnets.
- Draw the **TCP three-way handshake**, the connection-termination diagram and the **cwnd-versus-time graph** (slow start, congestion avoidance, Taho versus Reno). These are high-mark diagrams.
- **Compare** pairs: TCP vs UDP, DVR vs LSR, GBN vs SR, pure vs slotted ALOHA, POP3 vs IMAP, persistent vs nonpersistent HTTP.
- Memorise the **well-known port numbers**: 20/21 FTP, 22 SSH, 23 TELNET, 25 SMTP, 53 DNS, 80 HTTP, 110 POP3, 143 IMAP, 179 BGP, 520 RIP.
