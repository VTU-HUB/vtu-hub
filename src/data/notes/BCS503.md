## Module 1 — Finite automata

> **In short:** a **finite automaton** is a machine with a fixed number of states that reads a string one symbol at a time and says **accept** or **reject**. A DFA has exactly one move per symbol; an NFA may have several. Both recognise exactly the **regular languages**.

### Why study automata

**Automata theory** studies abstract machines and the problems they can solve.

- **Finite automata** model systems with a finite memory: lexical analysers, text search, protocols and digital circuits.
- **Grammars** model the structure of programming languages; parsers use them.
- **Complexity:** automata theory also asks what is **decidable** (solvable at all) and what is **tractable** (solvable efficiently). Turing machines (Module 5) answer this.
- **Structural representations:**
  - **Grammars** describe recursive structure, such as expressions.
  - **Regular expressions** describe text patterns, such as identifiers.

### Central concepts

- **Alphabet** Σ: a finite, non-empty set of symbols, for example {0, 1}.
- **String:** a finite sequence of symbols. The **empty string** ε has length 0.
- **Powers of an alphabet:**
  - Σᵏ is the set of strings of length k.
  - **Σ\*** is the set of all strings: Σ⁰ ∪ Σ¹ ∪ ….
  - **Σ⁺** is Σ\* minus {ε}.
- **Concatenation:** xy means x followed by y.
- **Language:** any subset L ⊆ Σ\*, such as the set of binary strings with an equal number of 0s and 1s.
- **Problem:** in automata theory, a problem means "is string w a member of language L?"

### Deterministic finite automata (DFA)

A DFA is a 5-tuple **A = (Q, Σ, δ, q₀, F)**:

- Q is a finite set of states.
- Σ is the input alphabet.
- **δ: Q × Σ → Q** is the transition function. Exactly **one** next state exists for each state and symbol.
- q₀ is the start state.
- F ⊆ Q is the set of accepting states.

The **extended transition function** δ̂ handles strings: δ̂(q, ε) = q and δ̂(q, wa) = δ(δ̂(q, w), a). The **language** of A is L(A) = { w | δ̂(q₀, w) ∈ F }. Languages accepted by DFAs are the **regular languages**.

Represent a DFA with a **transition diagram** (states as circles, accepting states as double circles, an arrow into the start state) or a **transition table** (start state marked →, accepting states marked \*).

**Design method:** decide what each state must "remember" about the input so far, then add the transitions.

- **Strings ending in 01:** three states, remembering "nothing useful", "seen 0" and "seen 01".
- **Strings with an even number of 0s and an even number of 1s:** four states, one for each parity pair.
- **Binary numbers divisible by 3:** three states, one for each remainder. Reading bit b in remainder r moves to (2r + b) mod 3.

### Nondeterministic finite automata (NFA)

An NFA is the same 5-tuple except **δ: Q × Σ → 2^Q**: a state and symbol can lead to a **set** of states, possibly empty. An NFA accepts w if **some** path for w ends in an accepting state.

- NFAs are often far smaller and easier to design. For example, "the third symbol from the end is 1" needs 4 NFA states but 8 DFA states.
- **Subset construction (NFA → DFA):**
  - Each DFA state is a set of NFA states.
  - The DFA start state is {q₀} (for an NFA **without** ε-moves; for an ε-NFA it is ECLOSE(q₀), see below).
  - δ_D(S, a) = ⋃ over p ∈ S of δ_N(p, a).
  - A DFA state is accepting if it contains an NFA accepting state.
  - Build only the reachable subsets.
- **Theorem:** a language is accepted by some DFA **if and only if** it is accepted by some NFA. The DFA can need up to 2ⁿ states.

```flow
Start: {q0} -> For each set S and symbol a, union the NFA moves -> New set? Add it as a DFA state -> Repeat until no new sets -> Sets containing a final state are final
```

### Application: text search

To find any of a set of keywords in text, build an NFA:

- The start state loops on every symbol.
- A chain of states spells out each keyword.

Convert it to a DFA with the subset construction, and the DFA scans the text in one pass. Tools like grep work this way.

### Finite automata with ε-transitions (ε-NFA)

An ε-NFA may move between states **without reading input**: δ: Q × (Σ ∪ {ε}) → 2^Q.

- **ECLOSE(q)**, the ε-closure, is every state reachable from q using only ε-moves, including q itself.
- **ε-NFA → DFA:** this is the subset construction with closures.
  - The start state is ECLOSE(q₀).
  - From a set S on symbol a, take the moves on a, then the ECLOSE of the result.
  - A state is accepting if the set contains an accepting state.
- **Equivalence:** DFA, NFA and ε-NFA all accept exactly the regular languages.

## Module 2 — Regular expressions and properties of regular languages

> **In short:** a **regular expression** describes a pattern using union, concatenation and star. Regular expressions and finite automata describe **the same languages**. The **pumping lemma** proves a language is *not* regular; **minimisation** gives the smallest DFA.

### Regular expressions

The operators, from highest to lowest precedence:

1. **Star** (closure): L\* = L⁰ ∪ L¹ ∪ L² ∪ ….
2. **Concatenation**: LM.
3. **Union**: L + M.

Notation warning: in this course **+ means union**. In programming tools (grep, Python) + means "one or more" and union is written |. Don't mix the two.

The basis cases are ε, ∅ and single symbols a.

Examples over {0, 1}:

- (0 + 1)\*01: strings ending in 01.
- 1\*(0 + ε)1\*: strings with at most one 0.
- (0 + 1)\*00(0 + 1)\*: strings containing 00.
- (ε + 1)(01)\*(ε + 0): strings of alternating 0s and 1s.

### Finite automata and regular expressions

The two are equivalent, and the course proves it both ways.

```flow
Regular expression -> epsilon-NFA -> NFA -> DFA -> Minimum DFA
DFA -> State elimination -> Regular expression
```

- **DFA → RE:** comes in two methods.
  - **Rᵢⱼ⁽ᵏ⁾ construction:** Rᵢⱼ⁽ᵏ⁾ = Rᵢⱼ⁽ᵏ⁻¹⁾ + Rᵢₖ⁽ᵏ⁻¹⁾ (Rₖₖ⁽ᵏ⁻¹⁾)\* Rₖⱼ⁽ᵏ⁻¹⁾.
  - **State elimination:** faster by hand. A clean way to apply it:
    1. Add a new start state with an ε-edge to the old start, and a new single final state with ε-edges from every old accepting state.
    2. Label each edge with a regular expression; merge parallel edges with +.
    3. Eliminate the old states one at a time. When removing state k, for every pair (i, j) update Rᵢⱼ := Rᵢⱼ + Rᵢₖ (Rₖₖ)\* Rₖⱼ (treat a missing edge as ∅).
    4. When only the new start and final states remain, the label on the edge between them is the answer.

    The textbook's equivalent shortcut eliminates states once per accepting state and reads off (R + SU\*T)\*SU\* for each, then takes the union.
- **RE → ε-NFA** (Thompson-style, by induction on the expression):
  - Basis: automata for ε, ∅ and a.
  - **Union:** a new start state with ε-moves into both machines.
  - **Concatenation:** an ε-move from the end of the first machine to the start of the second.
  - **Star:** ε-moves that allow skipping the machine or repeating it.
- **Algebraic laws:**
  - Union is commutative and associative.
  - Concatenation is associative.
  - ∅ is the identity for union and the annihilator for concatenation.
  - ε is the identity for concatenation.
  - (L\*)\* = L\*, ∅\* = ε, and L⁺ = LL\*.

### Proving languages not regular: the pumping lemma

**Pumping lemma for regular languages:** if L is regular, there is a constant n such that every w ∈ L with |w| ≥ n can be written **w = xyz** with:

1. y ≠ ε
2. |xy| ≤ n
3. **xyᵏz ∈ L for all k ≥ 0**

**Proof method** (a game against an adversary):

1. Assume L is regular and let n be the constant.
2. Choose a specific w ∈ L with |w| ≥ n.
3. Consider **every** split xyz allowed by conditions 1 and 2.
4. Find a k for which xyᵏz ∉ L. That contradicts the lemma.

**Classic example:** L = { 0ᵐ1ᵐ | m ≥ 0 }.

1. Take w = 0ⁿ1ⁿ. Because |xy| ≤ n, y consists only of 0s.
2. Pump with k = 0. The result has fewer 0s than 1s, so it is not in L.
3. Therefore L is not regular.

Other non-regular languages: { 0^(i²) }, { ww }, palindromes, and balanced parentheses.

### Closure properties of regular languages

Regular languages are closed under:

- **union**, **intersection**, **complement** (swap the accepting and non-accepting states of a complete DFA) and **difference**
- **reversal**, **star** and **concatenation**
- **homomorphism** and **inverse homomorphism**

**Intersection** uses the **product construction**: run both DFAs in parallel with states (p, q), and accept when both accept.

Closure is useful in proofs. For example, if L ∩ 0\*1\* is not regular, then L is not regular.

### Decision properties, equivalence and minimisation

**Decision properties** (all decidable for regular languages):

- **Emptiness:** is an accepting state reachable from the start state?
- **Membership:** run the DFA on the string.
- **Equivalence:** do two automata accept the same language?

**Equivalent states and the table-filling algorithm:** two states p and q are **equivalent** if, for every string w, δ̂(p, w) is accepting exactly when δ̂(q, w) is. To find them:

1. Mark every pair (accepting, non-accepting) as **distinguishable**.
2. Repeatedly mark (p, q) if, for some symbol a, the pair (δ(p, a), δ(q, a)) is already marked.
3. Unmarked pairs are equivalent.

**Minimisation:**

1. Remove unreachable states.
2. Merge equivalent states into blocks.

The result is the **unique minimum DFA** for the language, up to renaming the states.

**Testing equivalence of two DFAs:** run table filling on their combined states and check that the two start states are equivalent.

### Applications of regular expressions

- **UNIX regular expressions** extend the notation:
  - Character classes: [a-z], ., ^ and $.
  - Operators: + (one or more), ? (optional) and {n} (exactly n).
- **Lexical analysis:** tools such as lex turn regular expressions for tokens into one DFA, and use the longest match and rule priority to break ties.
- **Pattern finding in text:** extracting addresses or phone numbers.

## Module 3 — Context-free grammars and pushdown automata

> **In short:** a **context-free grammar** generates strings with rules like S → 0S1. It describes nesting (brackets, expressions) that finite automata cannot count. A **pushdown automaton** is a finite automaton plus a **stack**, and it accepts exactly the context-free languages.

### Context-free grammars (CFG)

A CFG is **G = (V, T, P, S)**: variables V, terminals T, productions P of the form A → α (with α ∈ (V ∪ T)\*), and the start symbol S.

- **Derivation:** ⇒ means one step, ⇒\* means zero or more steps.
  - A **leftmost derivation** always replaces the leftmost variable.
  - A **rightmost derivation** always replaces the rightmost variable.
- **Language:** L(G) = { w ∈ T\* | S ⇒\* w }. These are the **context-free languages (CFLs)**.
- **Examples:**
  - Palindromes: S → 0S0 | 1S1 | 0 | 1 | ε.
  - 0ⁿ1ⁿ: S → 0S1 | ε.
  - Expressions: E → E + E | E \* E | (E) | id.
- **Sentential form:** any string derivable from S, possibly still containing variables.

### Parse trees

A **parse tree** has these parts:

- The root is S.
- Interior nodes are variables, and each node's children match one production.
- The leaves, read left to right, form the **yield**.

**Equivalent statements:** for a CFG, these are all equivalent:

- A parse tree with yield w exists.
- A leftmost derivation of w exists.
- A rightmost derivation of w exists.

**Applications:** parsers (YACC) and markup languages (the structure of HTML and XML).

### Ambiguity in grammars and languages

A grammar is **ambiguous** if some string has **two different parse trees**, or equivalently two leftmost derivations. For example, E → E + E | E \* E | id is ambiguous for id + id \* id.

- **Removing ambiguity:** encode **precedence** and **associativity** with extra variables:
  - E → E + T | T
  - T → T \* F | F
  - F → (E) | id
- **Inherent ambiguity:** some languages have **no** unambiguous grammar at all. The example is { aⁱbʲcᵏ | i = j or j = k }.
- **Undecidability:** it is undecidable whether an arbitrary CFG is ambiguous.

### Pushdown automata (PDA)

A PDA is an ε-NFA with a **stack**:

**P = (Q, Σ, Γ, δ, q₀, Z₀, F)**

- Γ is the stack alphabet, and Z₀ is the initial stack symbol.
- δ(q, a, X) is a set of pairs (p, γ): in state q, reading a (or ε), with X on top of the stack, move to p and replace X with γ.

Key ideas:

- **Instantaneous description (ID):** (state, remaining input, stack contents). ⊢ means one move.
- **Two ways to accept:**
  - **By final state:** L(P) = { w | (q₀, w, Z₀) ⊢\* (q, ε, α), q ∈ F }.
  - **By empty stack:** N(P) = { w | (q₀, w, Z₀) ⊢\* (q, ε, ε) }.
  - The two are **equivalent**: each kind of PDA can be converted to the other.
- **Example: a PDA for { wwᴿ }.**
  1. Push symbols in state q₀.
  2. Guess the middle (an ε-move to q₁).
  3. Pop and match symbols in q₁.
  4. Accept when only Z₀ is left.

### Equivalence of PDAs and CFGs

- **CFG → PDA:**
  - Build a one-state PDA that simulates a **leftmost derivation** on its stack.
  - For a variable A on top: δ(q, ε, A) = { (q, β) | A → β }.
  - For a terminal a on top: δ(q, a, a) = { (q, ε) }.
  - Acceptance is by empty stack.
- **PDA → CFG:**
  - Use variables [pXq], meaning "the PDA goes from p to q while popping X".
  - Build productions from each transition.
- **Conclusion:** CFLs are exactly the languages accepted by PDAs.

### Deterministic PDA (DPDA)

A **DPDA** is a PDA that never has a choice of move.

- At most one move exists for any (q, a, X).
- If an ε-move exists for (q, X), no move on input may exist.

Properties:

- DPDAs accepting by final state accept a **proper superset of the regular languages** and a **proper subset of the CFLs**. For example, { wcwᴿ } is a DPDA language, but { wwᴿ } is not.
- **Unambiguous grammars:** every DPDA language has an unambiguous grammar, which is why parsers use deterministic subsets such as LR grammars.

## Module 4 — Normal forms and properties of CFLs

> **In short:** clean up a grammar (remove ε-productions, unit productions and useless symbols), then put it in **Chomsky Normal Form** (A → BC or A → a). The **CFL pumping lemma** proves a language is *not* context-free, for example 0ⁿ1ⁿ2ⁿ.

### Simplifying grammars

Simplification happens in this order:

```flow
Remove epsilon-productions -> Remove unit productions -> Remove useless symbols -> Convert to CNF
```

1. **Eliminate ε-productions:**
   - Find the **nullable** variables (those with A ⇒\* ε).
   - For every production, add versions with each subset of the nullable symbols removed.
   - Drop the A → ε productions. The new grammar generates L − {ε}.
   - **If ε ∈ L** (the start symbol is nullable) and you must keep it, add a new start symbol S₀ that never appears on a right-hand side, with S₀ → S | ε. S₀ → ε is then the only ε-production allowed.
2. **Eliminate unit productions (A → B):**
   - Find the **unit pairs** (A, B), where A ⇒\* B using only unit productions.
   - Give A all of B's non-unit productions.
3. **Eliminate useless symbols:**
   - Remove **non-generating** symbols (those that derive no terminal string).
   - Then remove **unreachable** symbols. The order matters.

### Chomsky Normal Form (CNF)

In **CNF** every production has the form **A → BC** or **A → a**. Every CFL without ε has a CNF grammar (if ε ∈ L, the convention allows the single extra production S₀ → ε, with S₀ never on a right-hand side). To convert:

1. Simplify the grammar (the three steps above).
2. For terminals inside long bodies, add A_a → a and substitute it.
3. Break bodies longer than 2 into chains: A → B₁C₁, C₁ → B₂C₂, and so on.

In CNF, a derivation of a string of length n takes exactly **2n − 1 steps**, and parse trees are binary. This is used in the **CYK** membership algorithm, O(n³).

**Greibach Normal Form (GNF):** every production has the form A → aα. It appears in some syllabi; know the definition.

### Pumping lemma for context-free languages

If L is a CFL, there is a constant n such that every z ∈ L with |z| ≥ n can be written **z = uvwxy** with:

1. **|vwx| ≤ n**
2. **vx ≠ ε**
3. **uvⁱwxⁱy ∈ L for all i ≥ 0**

The proof comes from a long path in a CNF parse tree, which must repeat a variable.

**Classic example:** L = { 0ⁿ1ⁿ2ⁿ } is **not context-free**.

1. Assume L is a CFL with pumping constant n. Take z = 0ⁿ1ⁿ2ⁿ, so z ∈ L and |z| = 3n ≥ n.
2. Let z = uvwxy be **any** split with |vwx| ≤ n and |vx| ≥ 1.
3. The 0-block and the 2-block are separated by n 1s, so a window of length ≤ n cannot reach both. Hence vwx lies inside 0ⁿ1ⁿ or inside 1ⁿ2ⁿ: it touches **at most two** of the three symbols.
4. Pump with i = 0 (z′ = uwy). Since |vx| ≥ 1, z′ loses at least one symbol, but only of the (at most two) symbols in vwx. At least one symbol keeps its count n while another drops below n.
5. So z′ does not have equal numbers of 0s, 1s and 2s: z′ ∉ L. (If v or x contained two different symbols, pumping up with i = 2 would also break the 0…1…2 order.)
6. Every allowed split fails, which contradicts the lemma. **L is not context-free.**

Other non-CFLs: { ww }, and { 0ⁱ1ʲ2ⁱ3ʲ }.

### Closure properties of CFLs

**Closed under:**

- **union**, **concatenation**, **star** and **reversal**
- **homomorphism** and **inverse homomorphism**
- **substitution**
- **intersection with a regular language** (run the PDA and the DFA in parallel)

**Not closed under:**

- **Intersection.** { 0ⁿ1ⁿ2ᵐ } ∩ { 0ᵐ1ⁿ2ⁿ } = { 0ⁿ1ⁿ2ⁿ }, which is not context-free.
- **Complement.** If CFLs were closed under complement, they would be closed under intersection too, by De Morgan's law.
- **Difference** (but L − R, with R regular, *is* a CFL).

**Decidable for CFLs:** emptiness, finiteness and membership (CYK). **Undecidable:** ambiguity, equivalence of two CFGs, and whether L = Σ\*.

## Module 5 — Turing machines and undecidability

> **In short:** a **Turing machine** is a finite control with an infinite read/write tape. By the Church–Turing thesis, anything that can be computed by a step-by-step procedure (an algorithm) can be computed by a Turing machine. Some problems, such as the **halting problem**, cannot be solved by any Turing machine: they are **undecidable**.

### Problems that computers cannot solve

Some problems cannot be solved by any program. The informal argument:

1. Suppose a program H could decide whether any program prints "hello, world" on a given input.
2. Build a program that does the opposite of what H predicts about itself.
3. This **self-reference** is a contradiction, so H cannot exist.

Undecidability proofs work by **reduction**: if problem P₁ is undecidable and P₁ reduces to P₂, then P₂ is also undecidable.

### The Turing machine

A TM is **M = (Q, Σ, Γ, δ, q₀, B, F)**:

- It has an infinite **tape** of cells. The **blank** B is in Γ but not in Σ.
- **δ(q, X) = (p, Y, D):** in state q reading X, write Y, move the head L or R, and go to state p.
- **Instantaneous description:** written as X₁…Xᵢ₋₁ q Xᵢ…Xₙ, with the head on Xᵢ.
- **Three possible outcomes** (Hopcroft–Ullman convention):
  - **Accept:** the TM enters a final state. It is assumed to halt there.
  - **Reject:** it halts (δ is undefined for the current state and symbol) in a non-final state.
  - **Loop:** it runs forever and never gives an answer.

  Halting alone does not mean acceptance; only halting in a final state does.

**Language classes:**

```flow
Regular -> Context-free -> Recursive (decidable) -> Recursively enumerable
```

- **Recursively enumerable (RE):** the languages accepted by some TM. The TM may loop forever on strings not in the language.
- **Recursive** (decidable): the TM halts on every input.
- **Hierarchy:** regular ⊂ CFL ⊂ recursive ⊂ RE.

**Design example: a TM for { 0ⁿ1ⁿ }.**

1. Mark the leftmost 0 as X.
2. Move right to the first 1 and mark it Y.
3. Return left to the X and repeat.
4. Accept when only Xs and Ys remain.

Practise writing the transition table and tracing the IDs for this machine.

### Programming techniques for Turing machines

- **Storage in the state:** the finite control remembers a symbol, for example "I have seen a 0".
- **Multiple tracks:** each tape cell holds a tuple, for example a mark plus a symbol.
- **Subroutines:** groups of states that do one job and return, such as copying or shifting.

### Extensions to the basic Turing machine

- **Multitape TM:** several tapes and heads. It is equivalent to a one-tape TM, with at most a **quadratic** slowdown.
- **Nondeterministic TM:** choices of moves. It is equivalent to a deterministic TM, which explores the possible moves breadth-first, though possibly with an exponential slowdown.
- **Restricted variants with the same power:** a semi-infinite tape, multistack machines (two stacks are enough) and counter machines.
- **Church–Turing thesis:** every effectively computable function (one computable by a mechanical step-by-step procedure) is computable by a TM. It is a **thesis**, not a theorem: "effectively computable" is an informal idea, so it cannot be proved, but no counterexample is known. TMs are therefore used as the formal definition of "algorithm".

### Undecidability: a language that is not RE

- **Encoding:** every TM can be encoded as a binary string, giving the "i-th TM" Mᵢ and the "i-th string" wᵢ.
- **Diagonalisation language:** **L_d = { wᵢ | wᵢ ∉ L(Mᵢ) }**, the strings not accepted by the machine they encode.
- **Theorem: L_d is not RE.**
  1. Suppose L_d = L(Mᵢ) for some i.
  2. Then wᵢ ∈ L_d ⇔ wᵢ ∉ L(Mᵢ) = L_d.
  3. That is a contradiction (diagonalisation).
- **Consequences:**
  - The complement of a recursive language is recursive.
  - If L and its complement are both RE, then L is recursive.
  - The **universal language** L_u = { (M, w) | M accepts w } is **RE but not recursive**. The **halting problem** is undecidable.

## Exam tips

- **Design questions carry the most marks:** DFA for a stated language, NFA → DFA by subset construction, ε-NFA → DFA, minimisation by table filling. Show the transition table and the final diagram.
- **Regular expression conversions:** know both directions (DFA → RE by state elimination; RE → ε-NFA by construction).
- **Pumping lemma proofs:** write the full argument. Choose w, then consider every allowed split, then pump to a contradiction. Use 0ⁿ1ⁿ (regular) and 0ⁿ1ⁿ2ⁿ (CFL).
- **Grammar questions:** show leftmost/rightmost derivations and parse trees, and prove ambiguity with two trees. CNF conversion must follow the order: ε-productions, then unit productions, then useless symbols.
- **PDA and TM:** practise one design each (wwᴿ or 0ⁿ1ⁿ), with transitions and an ID trace for a sample string.
